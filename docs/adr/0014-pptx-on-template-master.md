# 0014. Редактируемый PPTX собирается python-pptx на PowerPoint-мастере шаблона

- Дата: 2026-09-11
- Статус: принято
- Источник: [спека PPTX](../superpowers/specs/2026-09-11-pptx-export-design.md); [план](../superpowers/plans/2026-09-11-pptx-export.md), «Отклонения»; [заметка о ppt-rs](../notes/2026-09-11-ppt-rs-contrib.md); [template-contract.md](../template-contract.md#powerpoint-мастер)

## Контекст

Люди хотят дорабатывать презентацию в PowerPoint: править текст и графики, а не получать картинку.

## Решение

Модуль `pptx.py`. Необязательное поле `pptx` в `template.json` ведёт к `pptx.json`: мастер, сопоставление типов слайдов с макетами и заполнителями, палитра графиков; неизвестные ключи — ошибка. Текст — в заполнители макетов, графики — нативные со встроенной книгой, `notes` — в заметки. SVG растеризуется через typst. Файл собирается на каждый запрос в потоке, без кэша, колоду не меняет: `GET …/deck.pptx`, `pptx_url` (у шаблона без мастера — `null`). Сломанное сопоставление выключает только PPTX. В заголовке спеки остался статус «на ревью» — решение выкачено 2026-09-11.

## Отвергнутые варианты

- ppt-rs — размер слайда зашит 4:3, текст не в заполнителях, нет привязок к Python.
- Кэш готового файла — 24 слайда собираются за 0,26 с.
- Векторная вставка SVG; совпадение с PDF пиксель в пиксель; обратный путь PPTX → колода.

## Последствия

- (+) Файл правится в PowerPoint; сломанное сопоставление не роняет PDF.
- (−) Вид отличается от PDF.
- (−) `python-pptx<2`: код опирается на внутренности (`_sldIdLst`, `_spTree`).
- (−) Что PowerPoint откроет файл без «восстановить», доказывает только ручная приёмка.
