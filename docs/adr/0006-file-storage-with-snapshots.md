# 0006. Хранилище — файлы на диске: полные снимки версий, атомарная запись

- Дата: 2026-09-08
- Статус: принято
- Источник: [спека v1](../superpowers/specs/2026-09-08-typst-deck-design.md) §6; [план multiuser](../superpowers/plans/2026-09-09-multiuser.md)

## Контекст

В первой версии один процесс FastAPI. Нужны версии с откатом и никаких полуготовых файлов.

## Решение

Колода — `data/decks/<id>/`: `deck.json`, `versions/NNNNNN.json` (полный снимок), `assets/`, `uploads/`, `build/`, `chat.jsonl`. Запись через временный файл и `os.replace`, блокировка — `asyncio.Lock` на колоду. Удаление — перенос в `data/trash/`. В контейнере — volume `typst-deck-data`.

## Отвергнутые варианты

- БД — в первой версии не нужна; для многопроцессности предложен SQLite на томе ([0019](0019-multiuser-stages.md)).

## Последствия

- (+) Просто, переживает обрывы, резервная копия — `podman volume export`.
- (−) `versions/`, загрузки и `trash/` растут без чистки.
- (−) `list_decks()` читает каждый `deck.json` на запрос.
- (−) Несколько воркеров невозможны.
