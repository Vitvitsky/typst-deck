# 0001. Записываем архитектурные решения

- Дата: 2026-10-13
- Статус: принято
- Источник: этот журнал

## Контекст

Решения проекта разошлись по семи спекам, планам, README и заметкам вне репозитория. Чтобы понять, почему устроено так, приходилось читать спеки на сотни строк; часть причин жила только в памяти ассистента.

## Решение

Ведём журнал решений в `docs/adr/` по шаблону [template.md](template.md), по образцу Майкла Найгарда. ADR 0002–0020 восстановлены задним числом из спек и планов 2026-09-08…2026-09-13; дата в них — дата исходного решения. Правила ведения — [docs/README.md](../README.md#журнал-решений-adr).

## Отвергнутые варианты

- Держать решения только в спеках — спека описывает подпроект целиком, причину одного выбора в ней трудно найти и легко потерять при следующей спеке.

## Последствия

- (+) Одно место, где видно, что решено, почему и что чем заменено.
- (−) Ещё один документ, который надо не забыть написать вместе со спекой.
