# 0009. Делегированная личность: заголовок от прокси или ключ бота с on_behalf_of

- Дата: 2026-09-09
- Статус: принято, не реализовано
- Источник: [спека делегированной личности](../superpowers/specs/2026-09-09-delegated-identity-design.md); [план multiuser](../superpowers/plans/2026-09-09-multiuser.md), этап 1

## Контекст

Понятия пользователя нет, защита — общий Basic Auth: любой видит и правит чужие колоды, история показывает чужие промпты. Бот — делегат: в вызове участвуют бот и человек, который его попросил.

## Решение

Модуль `identity.py` с `Caller(user, via_bot)`. Порядок: `X-Service-Key` = `TYPST_DECK_SERVICE_KEY` → логин из `on_behalf_of` (нет — 422); заголовок `TYPST_DECK_USER_HEADER` (по умолчанию `X-Forwarded-User`); `TYPST_DECK_DEFAULT_USER`; иначе аноним. У колоды `owner` и `share_token`; `/d/{id}?s={token}` даёт чтение без правки и чата. Чужая колода — 404, не 403. Nginx затирает входящий `X-Forwarded-User`.

## Отвергнутые варианты

- OIDC/SAML — правильно, но дороже.
- Свои учётные записи с паролями.
- 403 на чужую колоду — позволяет перечислять чужие id.
- Чат для держателя ссылки.

## Последствия

- (+) Без собственной аутентификации; режим переключается одной переменной.
- (−) Вся защита держится на одной строке nginx, тестами не ловится.
- (−) Отзыва ссылки нет; забытый `DEFAULT_USER` в боевом контуре опасен.
