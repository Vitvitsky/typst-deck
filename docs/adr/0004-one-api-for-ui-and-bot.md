# 0004. Одно HTTP API для интерфейса и бота; для бота — синхронные обёртки

- Дата: 2026-09-08
- Статус: принято
- Источник: [спека v1](../superpowers/specs/2026-09-08-typst-deck-design.md) §1, §2 п.2, §8; [api.md](../api.md)

## Контекст

Сервисом пользуются люди в вебе и корпоративный чат-бот как инструментом.

## Решение

Ни одна операция не существует только в интерфейсе. Префикс `/api`, ошибки — `{"error": {"code", "message"}}`. Для бота — `POST /api/agent/create_deck`, `POST /api/agent/revise_deck`, `GET /api/agent/decks/{id}`: ждут задачу до `wait_seconds`, затем отдают `status: generating`. Ответ — `outline`, `pdf_url`, `pptx_url`, `edit_url`. Задачи живут в процессе (`jobs.py`), одна активная на колоду, вторая получает 409.

## Отвергнутые варианты

- MCP сразу — REST для бота есть сразу, MCP-обёртка отдельным шагом.
- Очередь задач вне процесса — вне первой версии.

## Последствия

- (+) Бот ничего не знает о слайдах; ссылка ведёт в ту же колоду.
- (−) Реестр задач в памяти: теряется при рестарте, `--workers` ломает данные ([0019](0019-multiuser-stages.md)).
