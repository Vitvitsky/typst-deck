# 0010. Ёмкость слотов объявляет шаблон; проверка до рендера; пределы измеряются

- Дата: 2026-09-09
- Статус: принято
- Источник: [спека ёмкости](../superpowers/specs/2026-09-09-slot-capacity-design.md); [план](../superpowers/plans/2026-09-10-slot-capacity.md), «Отклонение от спеки»; [template-contract.md](../template-contract.md#ёмкость-слотов)

## Контекст

Глобальные пределы (`TITLE_MAX=120`, `BULLET_MAX=200`) одинаковы для шаблонов, которые различаются кратно. 2026-09-09 четыре генерации подряд упали: переводы строки в `subtitle` выталкивали титул на вторую страницу.

## Решение

Раздел `slots` в `template.json`: тип → поле → `max`/`lines`/`count`. Объявление только сужает глобальные пределы. Пределы попадают в JSON Schema промпта и проверяются одним модулем `slots.py` — и в инструментах нейросети (`ERROR`), и в `PATCH` (422). Правка, уменьшающая старое нарушение, проходит; переезд в тесный шаблон даёт предупреждение. Последний рубеж — автоподбор кегля в шаблоне. Пределы меряет `scripts/measure_slots.py` по `measure.json` шаблона и ставит на 10–15 % ниже измеренного обрыва.

## Отвергнутые варианты

- Пределы в миллиметрах — упираются в метрики шрифта.
- Динамические Pydantic-модели — `model.py` остаётся статическим.
- Подсчёт строк после переноса в Python — дублирует typst.
- Расширение глобального потолка шаблоном — ломает переносимость колод.
- Правило запаса «полпункта кегля» — стоило бы 42 % ёмкости ячейки таблицы.

## Последствия

- (+) Модель видит пределы до генерации; одна проверка для чата и панели.
- (−) Автоматический перенос строк не покрыт — `lines` считает только `\n`.
- (−) Пределы перемеряются под каждый шаблон.
