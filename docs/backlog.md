## Дальше

- **Подпроект 2 «Файл оформления шаблона»** — шрифты, кегли, цвета, графика
  для Typst и PPTX в одном файле; туда переезжают временные ключи
  `text.quote/metric`, `trend`, `table` из `pptx.json`.
- **Подпроект 3 «Шаблоны»** — Lemana Tech на файле оформления, `default` и
  `dark`, стиль «как оформляет Claude».
- **Делегированная личность** — `identity.py`, `owner`, `share_token`,
  `require_deck` на ручках, `share_url`, затирание `X-Forwarded-User` в nginx
  ([ADR 0009](adr/0009-delegated-identity.md)). Вместе с ней: отзыв
  `share_token`, лог `DEFAULT_USER` при старте, тест на конфиг nginx.
- **MCP-обёртка** над тремя вызовами агентского API ([api.md](api.md)).
- **Сборка из готовой модели без нейросети** — вызов, который принимает колоду
  JSON (слайды по схеме модели) и шаблон и сразу рендерит: для процессов, где
  структура и текст уже известны и нужна дословность. Модель, проверка слотов
  и рендер уже есть; нужен маршрут вроде `POST /api/agent/render_deck` и
  ответ с ошибками валидации по полям. Сейчас создание всегда идёт через
  модель.
- **Тип слайда «процесс»** — 3–6 шагов стрелками или шевронами, рисует
  шаблон, в PPTX — нативные фигуры
  ([ADR 0021](adr/0021-process-slide-type.md)). После выкатки 15 типов;
  затем, возможно, «цикл» и «воронка».
- **Шаблон LemanaPro** — второе юрлицо, по контракту.
- **Многопользовательский режим, этапы 2–4**
  ([ADR 0019](adr/0019-multiuser-stages.md)):
  - этап 2 — блокировки, задачи и счётчик токенов вне процесса, `--workers`,
    свой `build.tmp` на воркер;
  - этап 3 — семафор рендеров, квоты токенов (429), чистка `versions/` и
    загрузок, срок хранения `trash/`;
  - этап 4 — индекс колод.
- Производительность интерфейса: gzip в nginx, `svgo`, PNG-миниатюры, SSE
  вместо опроса ([план multiuser](superpowers/plans/2026-09-09-multiuser.md)).

## Отложенные доработки

Набор слайдов (итоговые ревью планов C и D):

- [ ] Панель: правка не очищается между попытками сохранения; прочие правила
  модели (линия ≥ 2 подписей, длины) проверяются только сервером; ✕ без
  подписей для экранного диктора; «− Колонка» без подтверждения;
  `refresh()` после ответа чата перерисовывает панель.
- [ ] Lemana: заголовок с переводом строки после ~66 знаков или в капслоке —
  три строки вплотную к телу; подписи категорий на пределах (24×30)
  налезают у столбцов и срезаются у линий; неразрывное значение метрики
  в 16 широких знаков вылезает на соседнюю карточку; подписи видео
  и галереи — одна строка.
- [ ] `slots` не умеют сужать ячейки таблицы (`rows.cell`).

PPTX ([ADR 0014](adr/0014-pptx-on-template-master.md)):

- [ ] Ручная приёмка в PowerPoint: файл открывается без «восстановить», текст в
  зонах мастера, «Изменить данные» у графиков, заметки; кнопка «Скачать PPTX»
  видна у Lemana Tech и скрыта у `default`. Если PowerPoint предложит
  восстановить — пересохранить в нём и сравнить XML слайдов с нашим.
- [ ] SVG растеризуется в естественном размере: огромный `width` тормозит
  экспорт.
- [ ] `_drop_slides` не чистит `p14:sectionLst` и `custShowLst` — закрыть до
  подключения второго мастера (у мастера Lemana их нет).
- [ ] `"pptx": null`: контракт считает ошибкой, реестр — отсутствием поля.
  Свести к одному.
- [ ] Порядок импорта в `tests/test_corporate.py`.
- [ ] Замерить рост образа из-за lxml и Pillow.
- [ ] Подбор кегля в PPTX, если пределов слотов не хватит длинному заголовку.
- [ ] Мастера для `default` и `dark`.

Ёмкость и вёрстка ([ADR 0010](adr/0010-slot-capacity-in-template.md)):

- [ ] `lines` считает только явные `\n`; если автоматические переносы ломают
  вёрстку чаще — измерять через `typst query`.
- [ ] Пределы `slots` для `default` и `dark` не подобраны.
- [ ] Предупредить пользователей, что автокегль меняет вид старых колод.
