# Бэклог

Как вести — [docs/README.md](README.md#бэклог). Пункт — одна строка: что и
почему, ссылка на источник. Подробности — в спеке.

Обновлено: 2026-10-13. Порядок внутри раздела — порядок работы. Приоритет —
по вреду пользователям прода сейчас, затем по риску, зависимостям и цене.

## В работе (P1) — дефекты, которые видят пользователи

- [ ] **Вёрстка Lemana на пределах** (итоговое ревью плана D): неразрывное
  значение метрики в 16 широких знаков вылезает на соседнюю карточку; заголовок
  с переводом строки после ~66 знаков или в капслоке — три строки вплотную
  к телу; подписи категорий на пределах (24×30) налезают у столбцов и срезаются
  у линий; подписи видео и галереи — одна строка. Сначала замер
  (`scripts/measure_slots.py`), правка — в канон через worktree, после выкатки
  продукта, если нужно новое поле.
- [ ] **Ручная приёмка в PowerPoint** — нужен человек с PowerPoint и
  корпоративной сетью ([ADR 0014](adr/0014-pptx-on-template-master.md)).
  Образец на мастере Lemana, все 15 типов: файл открывается без
  «восстановить», текст в зонах мастера, «Изменить данные» у графиков, заметки;
  кнопка «Скачать PPTX» видна у Lemana Tech и скрыта у `default`; платформы
  плеера видео открываются из корпоративной сети. Если PowerPoint предложит
  восстановить — пересохранить в нём и сравнить XML слайдов с нашим. Итог
  решает судьбу блока PPTX в P2–P4.

## Дальше (P2) — быстрые выигрыши и снятие рисков

- **Сборка из готовой модели без нейросети** — `POST /api/agent/render_deck`:
  колода JSON и шаблон → рендер, ответ с ошибками валидации по полям. Модель,
  проверка слотов и рендер уже есть; нужна дословность там, где текст готов.
- **PPTX: SVG растеризуется в естественном размере** — огромный `width`
  тормозит экспорт.
- **Открытый вопрос — tool calling у корпоративного эндпоинта** (см. ниже):
  блокер переезда на внутреннюю модель, выясняется одним пробным запросом.
- **Алиас `lmru-hr:lemana-tech`** — неделю считать в логе приходы старого id,
  затем снять ([ADR 0012](adr/0012-template-aliases-and-migration.md)).
- **Метка версии рендера в `build/`** — пересобирать любую устаревшую сборку,
  а не только у колод, переписанных переносом. До подпроекта 2: он меняет
  контракт. Вместе с ней — хвосты ревью `25b43e0`: список колод не запускает
  ленивую сборку (превью — только после открытия); провал сборки страница
  показывает как «готово» с пустыми превью, без причины; перенос сносит
  `build/`, даже если переписаны только снимки `versions/`.
- **Шум шрифтов в `/api/health`** — у Lemana цепочка `"TT Interphases Pro",
  "TT Interphases Pro Trl", "Liberation Sans"`: основной найден, typst
  предупреждает о запасных. Не показывать запасные, если найден первый, иначе
  настоящая беда со шрифтом теряется в шуме.
- **Панель, остальное** (ревью плана C): правила модели (линия ≥ 2 подписей,
  длины) проверяются только сервером; ✕ без подписи для экранного диктора.

## Крупные направления (P3) — по зависимостям

- **Делегированная личность** — `identity.py`, `owner`, `share_token`,
  `require_deck` на ручках, `share_url`, затирание `X-Forwarded-User` в nginx
  ([ADR 0009](adr/0009-delegated-identity.md)). Вместе с ней: отзыв
  `share_token`, лог `DEFAULT_USER` при старте, тест на конфиг nginx. Первое,
  что нужно до корпоративного внедрения; если оно близко — в P1.
- **Подпроект 2 «Файл оформления шаблона»** — шрифты, кегли, цвета, графика
  для Typst и PPTX в одном файле; туда переезжают временные ключи
  `text.quote/metric`, `trend`, `table` из `pptx.json`.
- **Подпроект 3 «Шаблоны»** — Lemana Tech на файле оформления, `default` и
  `dark`, стиль «как оформляет Claude». Закрывает: пределы `slots` для
  `default` и `dark` не подобраны; мастера PPTX для `default` и `dark`.
- **Шаблон LemanaPro** — второе юрлицо, по контракту. До него —
  `_drop_slides` чистит `p14:sectionLst` и `custShowLst` (у мастера Lemana
  их нет, у второго могут быть).
- **MCP-обёртка** над агентским API ([api.md](api.md)) — после
  `render_deck`, чтобы обернуть и его.
- **Тип слайда «процесс»** — 3–6 шагов стрелками или шевронами, рисует
  шаблон, в PPTX — нативные фигуры
  ([ADR 0021](adr/0021-process-slide-type.md)). После подпроекта 2;
  затем, возможно, «цикл» и «воронка».
- **Многопользовательский режим, этапы 2–4**
  ([ADR 0019](adr/0019-multiuser-stages.md)):
  - этап 2 — блокировки, задачи и счётчик токенов вне процесса, `--workers`,
    свой `build.tmp` на воркер;
  - этап 3 — семафор рендеров, квоты токенов (429), чистка `versions/` и
    загрузок, срок хранения `trash/` (последние два можно раньше: данные
    растут и без пользователей);
  - этап 4 — индекс колод.
- Производительность интерфейса: gzip в nginx, `svgo`, PNG-миниатюры, SSE
  вместо опроса ([план multiuser](superpowers/plans/2026-09-09-multiuser.md)).

## По случаю (P4)

- [ ] `slots` не умеют сужать ячейки таблицы (`rows.cell`) — когда шаблону
  с широкой гарнитурой понадобится.
- [ ] `lines` считает только явные `\n` — если автоматические переносы начнут
  ломать вёрстку, измерять через `typst query`
  ([ADR 0010](adr/0010-slot-capacity-in-template.md)).
- [ ] PPTX: подбор кегля, если пределов слотов не хватит длинному заголовку —
  по итогам приёмки.
- [ ] `"pptx": null`: контракт считает ошибкой, реестр — отсутствием поля.
  Свести к одному — попутно с правкой контракта.
- [ ] Анализ таблиц кодом (`table_reader`) — до реализации собрать 5–10
  реальных отчётов и измерить долю прохождения валидатора
  ([ADR 0020](adr/0020-defer-table-reader.md)). Пока числа в графики печатает
  модель, `extract.py` обрезает таблицы на 200 строках.
- [ ] Сценарии с кликами в автотестах интерфейса
  ([ADR 0007](adr/0007-no-build-frontend.md)).
- [ ] Порядок импорта в `tests/test_corporate.py`; замерить рост образа из-за
  lxml и Pillow.
- [ ] ppt-rs: issue I1–I5 в upstream не отправлены
  ([заметка](notes/2026-09-11-ppt-rs-contrib.md)).

Осознанно не чиним: перенос колод `migrate_slides` атомарен по файлу, а не по
колоде; если процесс убить между файлами, повторный запуск доводит дело до
конца.
