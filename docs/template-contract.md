# Контракт шаблона typst-deck

Как сделать шаблон, который typst-deck подключит без правок кода. Эталон —
`template/` в этом репозитории: каждое правило ниже в нём выполнено, и когда
непонятно, как сделать, — смотрите туда.

## Шаблон — это каталог

Корень шаблона — каталог, который typst-deck видит в песочнице сборки как
`/template`. Всё, что шаблон импортирует, рисует и чем набирает текст, лежит
внутри него. Ссылка, ведущая наружу, локально сработает, а в контейнере нет:
туда шаблон попадает монтированием, и цели ссылки там не будет.

Корпоративный шаблон — это корень репозитория его канона. Всё, что относится к
typst-deck, лежит в папке `typst-deck/`, в корне только две точки входа:

```
<репозиторий канона>/
├── deck.typ          #import "typst-deck/adapter.typ": *
├── template.json
├── typst-deck/
│   ├── adapter.typ   семь функций контракта поверх канона
│   ├── fonts/        TTF/OTF
│   ├── measure.json  геометрия слотов для замера
│   └── pptx.json     сопоставление с PowerPoint-мастером (если он есть)
└── …канон как есть
```

## deck.typ

Экспортирует `deck` и 15 функций слайдов — ровно с такими параметрами:

```typst
#let deck(title: none, body)
#let slide-title(title: none, subtitle: none, author: none, department: none)
#let slide-agenda(title: none, items: ())
#let slide-section(title: none, subtitle: none)
#let slide-text(title: none, bullets: none)
#let slide-image(title: none, bullets: none, image: none, image-size: "medium", caption: none)
#let slide-columns(title: none, blocks: ())
#let slide-comparison(title: none, left: (:), right: (:))
#let slide-quote(text: none, author: none)
#let slide-chart(title: none, kind: "line", labels: (), series: (), unit: none, bullets: none)
#let slide-dual-chart(title: none, left: (:), right: (:))
#let slide-metrics(title: none, items: ())
#let slide-table(title: none, header: (), rows: (), numeric: ())
#let slide-gallery(title: none, images: ())
#let slide-video(title: none, poster: none, url: none, caption: none)
#let slide-final(title: none, contact: none)
```

Шаблон вправе импортировать эталонные функции из `template/deck.typ` и
переопределить часть: имя из второго импорта перекрывает то же имя из первого.
Экспортировать всё равно нужно все функции.

**Одна функция слайда — ровно одна страница.** Лишний текст обрезается
(`box(clip: true)`), а не переносится на следующую страницу: typst-deck сверяет
число страниц с числом слайдов и называет слайд, который вылез.

**Параметры.** `title`, `subtitle`, `author`, `department`, `caption`,
`contact`, `bullets` приходят как content — уже обёрнутые в маркер поля, по
которому работает правка по клику, — или `none`. Выводите их как есть и не
делайте над ними строковых операций. `bullets` — готовый список. `image` —
content или `none`. `labels`, `series`, `numeric` и числа — сырые массивы и
словари: графики шаблон рисует сам, падение — другим цветом, чем рост.

**Составные поля** (`items`, `blocks`, `left`, `right`, `header`, `rows`,
`images`) приходят массивами и словарями, а каждая их текстовая часть — уже
обёрнута маркером с именем поля верхнего уровня: у такого поля несколько зон
клика, любая открывает редактор всего поля.

**Что typst-deck вычисляет за шаблон:** `trend` у метрики (`"up"`, `"down"`
или `none` — по знаку в начале изменения; шаблон только красит); `numeric` у
таблицы (колонки, где все ячейки — числа; шаблон выравнивает их вправо); `url`
у видео — ссылка на ролик как есть; без `poster` заглушку рисует шаблон. Пакеты
`@preview` не используйте: у корпоративной сети может не быть доступа к реестру.

**Автор и подразделение** — отдельные блоки подписи, сначала человек, потом
подразделение.

## template.json

| поле | обязательно | смысл |
|---|---|---|
| `name` | да | имя в интерфейсе |
| `description` | нет | подпись в «Моих шаблонах» |
| `fonts` | нет | каталог шрифтов от корня; по умолчанию `fonts` |
| `measure` | нет | файл геометрии слотов для замера |
| `slots` | нет | ёмкость слотов |
| `pptx` | нет | сопоставление с PowerPoint-мастером от корня; без него экспорта в PPTX нет |
| `charts` | нет | ориентация столбцов — раздел «Ориентация столбцов»; без него столбцы всегда вертикальны |

## Шрифты

TTF/OTF — в каталоге из поля `fonts`. Семейства, которые называет шаблон,
обязаны совпадать с семействами внутри файлов (посмотреть: `fc-scan --format
"%{family}\n" файл.ttf`). Запасные семейства в списке допустимы. typst
предупреждает о каждом ненайденном, но проверка показывает лишь те, что
действительно нужны: первое семейство цепочки не найдено, а запасные — только
если первого нет. Цепочку она читает из кортежа строк в `.typ` шаблона, в том
числе из переменной. Это предупреждение, не ошибка. Ошибка — когда шрифты
шаблона не используются вовсе.

## Ёмкость слотов

Раздел `slots` объявляет, сколько вмещает каждое поле каждого типа слайда.
Пределы доходят до модели в схеме и проверяются при каждой правке. Объявление
может только сузить глобальные пределы typst-deck (120 знаков заголовка, 200 —
тезиса текстового слайда, 120 — вывода у графика, 6 тезисов на `image`,
4 — на графиках), не расширить.

Ячейку таблицы объявлением не сузить: `slots` принимает у `rows` только число
строк (`count`), а пути `rows.cell` нет — 38 знаков на ячейку задаёт сама модель.

| ключ | смысл | применим к |
|---|---|---|
| `max` | знаков | строковым полям и спискам строк (`bullets`, `labels`) |
| `lines` | явных строк (`\n` + 1) | строковым полям |
| `count` | элементов | спискам (`bullets`, `labels`, `data`, `series`) |

Пределы не угадываются, а меряются настоящим шрифтом:

```sh
uv run --project ~/projects/typst-deck python ~/projects/typst-deck/scripts/measure_slots.py <корень шаблона>
```

Скрипт печатает готовый раздел `slots`. Геометрию он берёт из `measure.json`:

```json
{
  "import": "templates/typst/slides_template.typ",
  "sample": "Итоги квартала по направлению данных и аналитики ",
  "list": "#set list(spacing: 0.7em)",
  "probes": [
    {"slide": "title", "field": "title", "width": "552mm", "height": "60mm",
     "size": "size-title", "weight": "bold", "font": "title-font"},
    {"slide": "image", "field": "bullets", "width": "349mm", "height": "250mm", "item": "40mm",
     "size": "size-body", "weight": "regular", "font": "body-font"}
  ]
}
```

- `import` — файл, после импорта которого `size`, `font` и оформление списка
  становятся выражениями Typst; путь от корня шаблона;
- `width` и `height` — зона поля в вёрстке, в мм;
- `item` есть только у списков: высота одного элемента, на которую меряется
  `max`; `count` меряется списком целиком, с интервалами между элементами;
- `list` — копия `#set list(...)` из вашего `deck()`; держите её в шаге с ним.

Автоподбор кегля в зонах заголовков (приём `fit-text` из эталона) —
рекомендация: пределы приблизительны, широкие знаки всё равно вылезают.

## Ориентация столбцов

Столбцы по категориям вертикальны, пока подписи помещаются под ними, иначе —
горизонтальны: подписи строками слева, столбцы вправо. Решение принимают оба
рендера по одному правилу из `template.json`, поэтому PDF и PPTX совпадают:
адаптер Typst читает файл сам (`json("../template.json")` от своего места),
экспорт PPTX — через `typst_deck/charts.py` и рисует линейчатую диаграмму.

```json
"charts": {"columns": {
  "full":    [[4, 18], [8, 11], [12, 8], [30, 7]],
  "bullets": [[4, 10], [8, 6], [12, 4], [30, 3]],
  "dual":    [[4, 9], [8, 5], [12, 3], [30, 2]]
}}
```

Пара `[L, N]`: подписи не длиннее `L` знаков (графем, как `str.clusters()`
у Typst) помещаются вертикально при `N` категориях и меньше. Столбцы вертикальны,
если подходит хоть одна пара раскладки. Раскладки: `full` — график во всё тело,
`bullets` — рядом с выводами, `dual` — половина двойного графика. Раскладки нет
в правиле — там столбцы вертикальны. Числа — замером ширины подписей настоящим
шрифтом, на 10–15 % ниже обрыва, как у ёмкости слотов. Сломанный раздел — столбцы
вертикальны, предупреждение при запуске и при выгрузке PPTX.

## PowerPoint-мастер

Если у шаблона есть PowerPoint-мастер, typst-deck умеет отдавать колоду
редактируемым PPTX: текст в заполнителях и зонах мастера, нативные графики,
заметки докладчика. Шрифт текста задаёт поле `font` (см. ниже); без него текст
берёт шрифты мастера как есть. Мастер и сопоставление лежат в шаблоне, поле
`pptx` в `template.json` — путь к сопоставлению:

```json
{
  "master": "references/master.pptx",
  "font": "Calibri",
  "text":  {"size": 28, "bullet": "FFDE00", "caption": "666666", "quote": 54, "metric": 80},
  "chart": {"palette": ["FFDE00", "1E1E1E", "00FFE0", "FF8700"], "negative": "FF2E00"},
  "trend": {"up": "1E1E1E", "down": "FF2E00"},
  "table": {"size": 20, "header_fill": "DDDDDD", "stripe_fill": "F8F8F8", "rule": "DDDDDD"},
  "slides": {
    "title":      {"layout": "Титульный слайд", "ph": {"title": 0, "subtitle": 1, "author": 21, "department": 21}},
    "agenda":     {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240]},
    "section":    {"layout": "Отбивочный слайд", "ph": {"title": 0, "subtitle": 1}},
    "text":       {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240]},
    "image":      {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240],
                   "image_width": {"small": 30, "medium": 42, "large": 55}, "gap": 15},
    "columns":    {"layout": "Блоки текста", "ph": {"title": 0, "blocks": [10, 11, 12]}},
    "comparison": {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240], "gap": 20},
    "quote":      {"layout": "Акцентный",    "ph": {},           "body": [83, 90, 511, 200]},
    "chart":      {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240],
                   "text_width": 38, "gap": 12, "heading": "Выводы"},
    "dual-chart": {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240], "gap": 20},
    "metrics":    {"layout": "Статистика",   "ph": {"title": 0}, "body": [83, 160, 564, 130], "gap": 15},
    "table":      {"layout": "Таблица",      "ph": {"title": 0}, "body": [83, 95, 564, 245]},
    "gallery":    {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240], "gap": 12},
    "video":      {"layout": "Стандартный",  "ph": {"title": 0}, "body": [83, 100, 564, 240]},
    "final":      {"layout": "Заключительный", "ph": {"title": 0, "contact": 1}}
  }
}
```

Сопоставление описывает все 15 типов слайда; тип без записи — ошибка. Нет
подходящего макета — кладите тип на общий макет с зоной тела: это решение
автора шаблона.

| ключ | смысл |
|---|---|
| `master` | путь к `.pptx` от корня шаблона |
| `font` | шрифт всего текста в PPTX, необязателен. Экспорт ставит его вместо явных латинских гарнитур в теме, мастерах и макетах (ссылки на шрифт темы остаются). В файл шрифт не встраивается — PowerPoint возьмёт установленный на машине |
| `text.size`, `text.bullet`, `text.caption` | кегль тезисов (пт); цвет маркера тезисов и номеров повестки; цвет подписей — картинки, автора цитаты, подписи метрики |
| `text.quote`, `text.metric` | кегль цитаты и крупного числа метрики, пт |
| `chart.palette`, `chart.negative` | цвета серий по кругу (первый — рост у гистограммы с одной серией), цвет падения |
| `trend.up`, `trend.down` | цвет изменения метрики: со знаком «+» и со знаком «-» или тире |
| `table.size`, `table.header_fill`, `table.stripe_fill`, `table.rule` | кегль ячеек, заливка шапки, заливка чётных строк, цвет тонких линий |
| `slides.<тип>.layout` | имя макета мастера |
| `slides.<тип>.ph` | поле → idx заполнителя макета; у заголовка idx 0 |
| `ph.blocks` | только у `columns`: список idx не короче трёх — блоки в заполнителях мастера; тогда `body` и `gap` не задаются, лишние заполнители удаляются |
| `body` | зона тела `[x, y, w, h]` в мм — у всех типов, кроме `title`, `section`, `final` и `columns` с `ph.blocks` |
| `image_width` | у `image`: ширина картинки в % от зоны для `small`/`medium`/`large`, число 1–90 |
| `text_width` | у `chart`: ширина колонки тезисов, % от зоны, число 1–90 |
| `gap` | зазор между колонками, мм — у `image`, `columns` (с зоной), `comparison`, `chart`, `dual-chart`, `metrics`, `gallery` |
| `heading` | у `chart`: заголовок колонки тезисов, необязателен |

Ключи оформления `text.quote`, `text.metric`, `trend` и `table` временные: они
переедут в файл оформления шаблона (подпроект 2). Все ключи, кроме `font` и
`heading`, обязательны там, где они бывают, и запрещены там, где не бывают;
неизвестные — ошибка. Цвета — hex `RRGGBB`, без `#`. Каждое поле, которое не
идёт в зону тела, обязано быть в `ph`: у `title` — `title`, `subtitle`,
`author`, `department`; у `section` — `title`, `subtitle`; у `final` — `title`,
`contact`; у `quote` — ничего; у остальных — `title`. Несколько полей на одном
idx становятся абзацами в порядке модели. Заполнитель макета, которому нечего
дать, удаляется со слайда; номер слайда переносится, если он есть в макете.

Как экспорт рисует тела:

- **agenda** — нумерованный список, номер цвета маркера;
- **text** — тезисы во всю зону;
- **columns** — жирный заголовок блока, затем текст; в зоне — равные колонки;
- **comparison** — две колонки: жирный заголовок и тезисы;
- **quote** — текст по центру зоны по обеим осям, автор ниже цветом подписи;
- **chart** — `bar` с одной серией красится по знаку и подписывает значения,
  с несколькими — по палитре с легендой; `line` — по палитре; тезисы, если
  есть, — колонкой слева шириной `text_width`;
- **dual-chart** — два нативных графика в колонках, над каждым подпись стороны;
- **metrics** — равные колонки: крупное число, подпись, изменение цветом тренда;
- **table** — нативная таблица: жирная шапка на заливке, «зебра», тонкие линии,
  числовые колонки вправо; строка не выше 15 мм;
- **gallery** — 2 и 3 картинки в ряд, 4 — сеткой 2×2, каждая вписана в клетку,
  подпись под ней;
- **video** — обложка с гиперссылкой на ролик и подпись. Рамка повторяет
  пропорции обложки; без обложки — заглушка 16:9: фон `table.header_fill`, по
  центру «▶» цвета `text.bullet`.

Пропавший файл — картинка или обложка — не роняет экспорт: слайд собирается
без него, причина пишется в лог. Клетка галереи без картинки остаётся пустой,
у видео без обложки — заглушка.

Посмотреть имена макетов и idx заполнителей можно скриптом ниже. Экспорт
объединяет макеты всех мастеров файла; при одинаковых именах берётся макет
первого мастера — номер мастера скрипт печатает первым. Заполнители даты,
колонтитула и номера слайда экспорт не переносит, их idx в `ph` не годятся —
скрипт их не показывает:

```sh
uv run --project ~/projects/typst-deck python -c "
from pptx import Presentation; from pptx.enum.shapes import PP_PLACEHOLDER as P; import sys
skip = {P.DATE, P.FOOTER, P.SLIDE_NUMBER}
prs = Presentation(sys.argv[1])
for i, m in enumerate(prs.slide_masters, 1):
    for l in m.slide_layouts:
        print(i, l.name, [(p.placeholder_format.idx, p.name) for p in l.placeholders
                          if p.placeholder_format.type not in skip])" <мастер.pptx>
```

### Подключить мастер — по шагам

1. Положите мастер `.pptx` в репозиторий канона, например в `references/`.
2. Посмотрите макеты и idx скриптом выше и выберите макет на каждый из 15
   типов слайда.
3. Напишите `typst-deck/pptx.json` по образцу выше. Зону тела удобно
   отмерить от заполнителя заголовка: тот же левый край, ниже заголовка, выше
   номера слайда.
4. Добавьте в `template.json` поле `"pptx": "typst-deck/pptx.json"`.
5. Проверьте шаблон — правило 7 сверит сопоставление с мастером и выгрузит
   образец (раздел «Проверка»).
6. Выгрузите образец в файл и откройте его в PowerPoint:

   ```sh
   uv run --project ~/projects/typst-deck python -c "
   import sys; from pathlib import Path
   from typst_deck.contract import SAMPLE_DECK, write_sample_assets; from typst_deck.pptx import export_pptx
   t, d = Path(sys.argv[1]), Path('sample-assets'); write_sample_assets(d)
   Path('sample.pptx').write_bytes(export_pptx(SAMPLE_DECK, t, sys.argv[2], d / 'assets'))" \
     <корень шаблона> typst-deck/pptx.json
   ```

   Файл должен открыться без предложения восстановить, текст — стоять в зонах
   мастера, «Изменить данные» у графиков — работать. Ролик образца — заглушка
   в несколько байт и не проигрывается; это нормально.
7. Шрифт из `font` в файл не встраивается: выбирайте тот, что есть у
   получателей (Calibri есть в любой установке Office).

Если шаблон уже подключён к серверу, шаги 1–7 делайте на копии канона, а не в
каталоге, который смонтирован в сервис, — см. «Подключение».

## Проверка

```sh
uv run --project ~/projects/typst-deck python -m typst_deck.templates <корень шаблона>
```

Семь правил; нарушение любого — ошибка:

1. есть `deck.typ` и `template.json` с `name`, `slots` проходят без единого
   отброшенного ключа;
2. образец — по слайду каждого типа — собирается, страниц столько же, сколько
   слайдов;
3. переросший текст и восемь переводов строки в титульном, разделительном и
   финальном слайдах не выносят слайд на вторую страницу;
4. у каждого текстового поля образца есть маркер правки;
5. слайды, заполненные ровно по объявленным пределам, собираются по одному на
   страницу;
6. шрифты из каталога шаблона используются: образец без системных шрифтов с
   этим каталогом и без него собирается по-разному.
7. если есть `pptx`: сопоставление читается, макеты с такими именами и
   заполнители с такими idx есть в мастере, зоны лежат внутри слайда, образец
   из 15 слайдов — с картинками — экспортируется и открывается заново.

При старте сервис проверяет каждый подключённый шаблон мягче. Сломанным
считается только шаблон, который не может работать (правила 1 — файлы — и 2):
он скрыт из выбора, а колоды на нём получают понятную ошибку. Правило 6 и
отброшенные ключи `slots` — предупреждения в `/api/health`.
Нарушение правила 7 при старте выключает у шаблона только экспорт в PPTX:
причина видна в `/api/health` (`templates.pptx_off`), PDF работает.

## Подключение

Id шаблона — имя каталога, под которым реестр видит его корень.

На сервере корень монтируется только на чтение, вторым корнем шаблонов:

```ini
# ~/stack/quadlet/typst-deck.container
Volume=%h/projects/<канон>:/corp/<id>:ro
Environment=TYPST_DECK_TEMPLATES_DIR=/app/templates:/corp
```

Локально — ссылкой: `ln -sfn ~/projects/<канон> ~/corp-templates/<id>`;
`scripts/dev.sh` подключает `~/corp-templates` сам.

**Смонтированный канон — это прод.** Сервис читает `template.json`,
`pptx.json` и файлы Typst при каждой сборке и каждом экспорте, поэтому правка
в смонтированном каталоге — даже незакоммиченная — сразу видна пользователям;
рестарт нужен только стартовой проверке. Отсюда два правила:

- новое поле в `template.json` или `pptx.json` появляется в каноне только
  после того, как выкачена версия typst-deck, которая его знает: старая
  отвергает неизвестные ключи `pptx.json`, и экспорт в PPTX отвечает 422;
- правку готовят на копии — например, в git worktree канона:

  ```sh
  git -C ~/projects/<канон> worktree add ~/projects/<канон>-wip -b wip
  python -m typst_deck.templates ~/projects/<канон>-wip   # из рабочей копии typst-deck
  TYPST_DECK_TEMPLATES_DIR=templates:<каталог со ссылкой <id> на копию> scripts/dev.sh
  ```

  и только проверенную вливают в ветку, которую видит сервис.

Сменили id — задайте алиас, пока внешние вызовы помнят старый:
`TYPST_DECK_TEMPLATE_ALIASES=старый:новый`. Колоды переносит
`python -m typst_deck.migrate_template старый новый` (при остановленном
сервисе).

Алиас разрешается в один шаг, без цепочек: из `a:b,b:c` не следует `a:c` —
каждый старый id ведите сразу в действующий (`a:c,b:c`). Кривое значение
`TYPST_DECK_TEMPLATE_ALIASES` (пара без `:` или с пустой стороной) не даёт
сервису стартовать — это нарочно.
