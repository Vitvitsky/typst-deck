# Экспорт колоды в редактируемый PPTX — проектная спецификация

Дата: 2026-09-11. Статус: **на ревью**.

## 1. Цель и границы

Люди хотят дорабатывать презентацию в PowerPoint: править текст, тезисы и
графики. Сейчас typst-deck отдаёт только PDF и веб-версию.

**Задача:** кнопка «Скачать PPTX» и ссылка для бота. Файл собирается из модели
колоды на PowerPoint-мастере шаблона: текст стоит в заполнителях и зонах
мастера, графики — нативные диаграммы PowerPoint, заметки — заметки докладчика.

**В границы входит:**

- модуль экспорта на python-pptx;
- необязательное поле `pptx` в `template.json` и файл сопоставления, который
  описывает, как типы слайдов ложатся на макеты мастера;
- правило 7 контракта шаблона: проверка сопоставления;
- эндпоинт скачивания, `pptx_url` в ответах API, кнопки в интерфейсе;
- сопоставление для Lemana Tech — коммит в репозиторий канона.

**В границы не входит:**

- мастера для `default` и `dark`: кнопки у них не будет, пока им не сделают
  мастер;
- совпадение с PDF «пиксель в пиксель»: оформление берётся из мастера, шрифт — из
  его темы;
- обратный путь PPTX → колода;
- векторная вставка SVG (картинки SVG идут растром, см. §5.4);
- кэш готового PPTX: файл собирается на каждый запрос.

## 2. Решения из обсуждения

| вопрос | решение |
|---|---|
| зачем PPTX | редактировать в PowerPoint, а не просто получить файл |
| у каких шаблонов кнопка | только у тех, у которых есть PowerPoint-мастер |
| кто получает | и интерфейс, и бот через агентское API |
| шрифт | как в мастере: шрифты темы, явно не задаём |
| чем собирать | python-pptx по сопоставлению из шаблона |

ppt-rs рассматривался и отклонён: зашитый размер слайда 4:3, текст не
в заполнителях, 7 фиксированных макетов, нет цвета точек графика и привязок к
Python. Подробности и черновики issue — `docs/notes/2026-09-11-ppt-rs-contrib.md`.

## 3. Что установлено

**По коду typst-deck (проверено 2026-09-11):**

- Модель знает шесть типов слайдов (`model.py`): `title`, `section`, `image`,
  `bar-chart`, `chart`, `final`. Поля: `title`, `subtitle`, `author`,
  `department`, `bullets`, `image`, `image_size`, `caption`, `data`, `labels`,
  `series`, `unit`, `contact`, `notes`.
- Картинки колоды лежат в `<колода>/assets/`, допустимы `.png`, `.jpg`, `.svg`
  (`store.py`, `ASSET_EXT`). Пропавшую картинку рендер PDF пропускает с
  предупреждением.
- PDF собирается лениво (`service.pdf`); сломанный или пропавший шаблон — 422
  с причиной (`service.template`), сбой компиляции — 500 `render`.
- Ответ колоды несёт `template` из `TemplateInfo.public()`; агентский ответ
  строится из него и отдаёт `pdf_url`.
- Путь «внутрь шаблона» проверяет `resolve_fonts` (`render.py`).
- В модели любая строка может содержать управляющие символы и переводы строки.

**По мастеру Lemana Tech** (`references/lm-tech_template.pptx` в каноне, 2 МБ):

- слайд 677×381 мм, 10 макетов;
- заполнители (idx, геометрия в мм):

| № | макет | заполнители |
|---|---|---|
| 1 | Титульный слайд | title (0); body idx 1 — x83 y164 610×53; body idx 21 «Author and Date» — x83 y299 610×18; номер |
| 3 | Отбивочный слайд 2 | фон `1E1E1E`; title (0); body idx 1 |
| 4 | Стандартный | title (0) — x83 y54 564×34; номер |
| 7 | График | как «Стандартный», но заголовок с x40 |
| 10 | Заключительный | title (0); body idx 1 и idx 10 — два блока контактов |

- цвета канона: жёлтый `FFDE00`, тёмный `1E1E1E`, бирюзовый `00FFE0`, оранжевый
  `FF8700`, красный `FF2E00`, серый `666666`.

**По python-pptx** (из документации и кода библиотеки, у нас не проверено —
первые тесты плана это закрепят):

- `add_slide` копирует заполнители макета, кроме даты, колонтитула и номера
  слайда;
- в тексте `"\n"` даёт новый абзац, `"\v"` — разрыв строки внутри абзаца;
- lxml отвергает управляющие символы в тексте (`ValueError`);
- `add_picture` не принимает SVG;
- при сохранении пишутся только части, достижимые по связям, поэтому удалённые
  слайды мастера в файл не попадают.

## 4. Сопоставление шаблона

### 4.1 Где лежит

В `template.json` появляется необязательное поле `"pptx"` — путь к файлу
сопоставления от корня шаблона, например `"typst-deck/pptx.json"`. Путь
проверяется так же, как `fonts`: только внутрь шаблона. Для этого проверка из
`resolve_fonts` выносится в общий помощник `inside_template(template_dir, rel,
field)` в `render.py`.

### 4.2 Формат

```json
{
  "master": "references/lm-tech_template.pptx",
  "text": {"size": 28, "bullet": "FFDE00", "caption": "666666"},
  "chart": {"palette": ["FFDE00", "1E1E1E", "00FFE0", "FF8700"], "negative": "FF2E00"},
  "slides": {
    "title":     {"layout": "Титульный слайд", "ph": {"title": 0, "subtitle": 1, "author": 21, "department": 21}},
    "section":   {"layout": "Отбивочный слайд 2", "ph": {"title": 0, "subtitle": 1}},
    "image":     {"layout": "Стандартный", "ph": {"title": 0}, "body": [83, 100, 564, 240],
                  "image_width": {"small": 30, "medium": 42, "large": 55}, "gap": 15},
    "bar-chart": {"layout": "Стандартный", "ph": {"title": 0}, "body": [83, 100, 564, 240],
                  "text_width": 38, "gap": 12, "heading": "Выводы"},
    "chart":     {"layout": "Стандартный", "ph": {"title": 0}, "body": [83, 100, 564, 240],
                  "text_width": 38, "gap": 12, "heading": "Выводы"},
    "final":     {"layout": "Заключительный", "ph": {"title": 0, "contact": 1}}
  }
}
```

| ключ | обязателен | смысл |
|---|---|---|
| `master` | да | путь к `.pptx` от корня шаблона, только внутрь шаблона |
| `text.size` | да | кегль тезисов, пт; подпись к картинке — 0,7 от него |
| `text.bullet` | да | цвет маркера тезисов, hex без `#` |
| `text.caption` | да | цвет подписи к картинке |
| `chart.palette` | да, ≥ 1 цвет | цвета серий по кругу; первый — цвет роста у гистограммы |
| `chart.negative` | да | цвет столбцов с отрицательным значением |
| `slides` | да, все шесть типов | раскладка по типам |
| `slides.*.layout` | да | имя макета мастера (`<p:cSld name>`) |
| `slides.*.ph` | да | поле → idx заполнителя макета; у заголовка idx 0 |
| `slides.*.body` | у `image`, `bar-chart`, `chart` | зона тела `[x, y, w, h]` в мм |
| `image_width` | у `image` | ширина картинки в % от зоны для `small`/`medium`/`large`, 1–90 |
| `text_width` | у `bar-chart`, `chart` | ширина колонки тезисов в % от зоны, 1–90 |
| `gap` | у `image`, `bar-chart`, `chart` | зазор между колонками, мм |
| `heading` | нет | заголовок колонки тезисов на слайдах с графиками |

Неизвестные ключи — ошибка: опечатка не должна тихо выключать настройку.

### 4.3 Правила полноты

- Каждое текстовое поле типа, которое не уходит в зону тела, обязано быть в `ph`,
  иначе его текст тихо пропадёт. В `ph` должны быть: у `title` — `title`,
  `subtitle`, `author`, `department`; у `section` — `title`, `subtitle`; у
  `final` — `title`, `contact`; у `image`, `bar-chart`, `chart` — `title`.
- Тезисы, картинка, подпись и график всегда идут в зону `body`, `notes` — в
  заметки докладчика; в `ph` их не пишут.
- Несколько полей на одном idx допустимы: они становятся абзацами в порядке полей
  модели (для титульного: `author`, затем `department`).
- Каждый idx из `ph` должен существовать в указанном макете; зона `body` — лежать
  внутри слайда мастера.

## 5. Экспорт

### 5.1 Интерфейс модуля

Новый модуль `src/typst_deck/pptx.py`:

- `class MappingError(ValueError)` — всё, что не так с сопоставлением или
  мастером; текст пригоден для человека;
- `load_mapping(template_dir, rel) -> Mapping` — читает и проверяет структуру
  (pydantic-модели с `extra="forbid"`), путь к мастеру и правила §4.3, кроме
  сверки с мастером;
- `open_master(template_dir, mapping) -> Presentation` — открывает мастер,
  сверяет имена макетов, idx заполнителей и зоны с размером слайда;
- `export_pptx(deck, template_dir, mapping_rel, assets_dir, typst_bin) -> bytes`.

Контракт и экспорт зовут одни и те же `load_mapping` и `open_master`, так что
проверка и работа не расходятся.

### 5.2 Порядок сборки

1. Прочитать сопоставление, открыть мастер.
2. Удалить слайды-образцы мастера (элемент `sldId` и связь).
3. Для каждого слайда колоды:
   1. добавить слайд на макете `slides.<тип>.layout`;
   2. разложить поля по заполнителям `ph`, при нескольких полях на idx —
      абзацами;
   3. удалить заполнители, которые остались пустыми: поле пустое или макету
      нечего дать (idx 10 у заключительного). Иначе при правке видна подсказка
      вроде «Уровень текста 1…»;
   4. если в макете есть заполнитель номера слайда, добавить его на слайд с полем
      номера (`<a:fld type="slidenum">`): при перестановке слайдов PowerPoint
      пересчитает номера;
   5. включить заголовку автоподбор PowerPoint (`normAutofit`);
   6. разложить тело (§5.3), если тип его имеет;
   7. заметки — в заметки докладчика.
4. Сохранить в память и вернуть байты.

Шрифт нигде не задаётся: текст наследует шрифты темы мастера.

### 5.3 Зона тела

**Тезисы.** Надпись с абзацами, маркер `•` цвета `text.bullet`, кегль
`text.size`, перенос по словам, без автоподбора.

**`image`:**

- картинка есть и нашлась: ширина картинки — `image_width[image_size]` % от
  ширины зоны, колонка тезисов — остаток минус `gap`;
- картинка вписывается в свою колонку с сохранением пропорций и прижимается к
  верху;
- при непустой подписи под картинкой оставляется полоса 15 мм под подпись:
  курсив, цвет `text.caption`, кегль 0,7 × `text.size`;
- картинки нет или она не нашлась: тезисы на всю зону.

**`bar-chart` и `chart`:**

- тезисы есть: колонка тезисов шириной `text_width` % слева, первым абзацем без
  маркера — `heading` жирным (если задан); график справа на остаток минус `gap`;
- тезисов нет: график на всю зону.

### 5.4 Графики

- **`bar-chart`:** гистограмма, одна серия. Цвет каждого столбца по знаку:
  значение ≥ 0 — `palette[0]`, < 0 — `negative`; `invert_if_negative` выключен.
  Подписи значений включены, формат `General" <unit>"` (без единицы — `General`).
  Без легенды и сетки.
- **`chart`:** линейный график с маркерами, серия i — цвет
  `palette[i % len(palette)]`, легенда сверху, единица — подпись оси значений.
  Без сетки.
- Данные лежат во встроенной книге, в PowerPoint их правят через «Изменить
  данные».

### 5.5 Текст

- Управляющие символы U+0000–U+001F, кроме `\t` и `\n`, вычищаются.
- `\n` внутри поля становится разрывом строки (`\v` для python-pptx), а не новым
  абзацем: так тезис с переводом строки остаётся одним пунктом.
- Длина не подбирается под зону, как `fit-text` в PDF. Текст держат пределы
  слотов; заголовкам включён автоподбор PowerPoint, но он срабатывает, когда
  текст правят.

### 5.6 Картинки SVG

python-pptx SVG не вставляет, а колода их принимает. SVG растеризуется в PNG
через typst: временный документ
`#set page(width: auto, height: auto, margin: 0pt)` + `#image("x.svg")`,
`typst compile --format png --ppi 200`. Функция `rasterize_svg` живёт в
`render.py` рядом с остальными вызовами typst. Сбой растеризации — как пропавшая
картинка: слайд без неё, предупреждение в лог.

## 6. Реестр, API, интерфейс

### 6.1 Реестр

- `TemplateInfo.pptx: Path | None` — путь к файлу сопоставления. `None`, если
  поля нет, путь ведёт наружу (предупреждение в лог) или PPTX у шаблона выключен
  стартовой проверкой.
- `TemplateRegistry.pptx_off: dict[str, str]` — id → причина выключения;
  заполняет `check_all` (§7).
- `public()` отдаёт `"pptx": true/false`.
- Реестр мастер не открывает: на каждый `get()` только путь.

### 6.2 API

- `GET /api/decks/{id}/deck.pptx`:
  - 200, `application/vnd.openxmlformats-officedocument.presentationml.presentation`,
    `Content-Disposition: attachment` с именем из названия колоды (первые 60
    знаков, `filename*` в UTF-8, как у `FileResponse`);
  - сборка в `asyncio.to_thread`; колода читается снимком, без блокировки;
    `build/` не трогается, новой версии и записи в чате нет.
- `deck_response` добавляет `"pptx_url"`: ссылку, когда у шаблона
  `pptx` не `None`, иначе `null`. Ключ есть всегда, чтобы у клиентов не менялась
  схема. `agent_response` передаёт его дальше рядом с `pdf_url`.
- `list_decks` добавляет каждой колоде `"pptx": true/false`.

### 6.3 Интерфейс

- Страница колоды: кнопка «Скачать PPTX» рядом с «Скачать PDF». Видна, когда
  `template.pptx` истинно и в колоде есть слайды; сборки `build/` не ждёт.
- Список колод: маленькая кнопка «PPTX» рядом с «PDF» при `pptx: true`.

## 7. Контракт: правило 7

Правило действует, только если в `template.json` есть `pptx`.

**Проверка:** `load_mapping` и `open_master` проходят, а образец `SAMPLE_DECK`
экспортируется, и файл снова открывается python-pptx с тем же числом слайдов.

**Режимы:**

- **полный** (автор шаблона, сборка образа, `python -m typst_deck.templates
  <каталог>`) — нарушение является ошибкой;
- **стартовый** — нарушение даёт предупреждение: шаблон не сломан, PDF работает,
  PPTX у шаблона выключен, причина записана в `pptx_off` и видна в
  `/api/health`.

`Report` получает отдельный список `pptx`: в полном режиме его сообщения
добавляются к ошибкам, в стартовом — к предупреждениям, а `check_all` по нему
заполняет `pptx_off`.

`docs/template-contract.md` получает раздел «PowerPoint-мастер»: поле `pptx`,
формат из §4.2, правила §4.3, правило 7 в разделе «Проверка».

## 8. Ошибки

| ситуация | где ловим | ответ |
|---|---|---|
| колоды нет | эндпоинт | 404 |
| шаблон сломан или не найден | `service.template()` | 422 с причиной |
| у шаблона нет поля `pptx` | эндпоинт | 422: «у шаблона «X» нет PowerPoint-мастера» |
| PPTX выключен стартовой проверкой | эндпоинт, по `pptx_off` | 422: «экспорт в PPTX у шаблона «X» выключен: <причина>» |
| сопоставление или мастер испортились после старта | экспорт, `MappingError` | 422 с текстом ошибки |
| картинки нет в `assets/` или SVG не растеризуется | экспорт | слайд без картинки, предупреждение в лог |
| прочее исключение при сборке | эндпоинт | 500 `render` с текстом, трейс в лог |

  `null` без него, у агента тоже;
- после экспорта версия колоды прежняя.

**`tests/test_corporate.py`** на `CORP_PARAMS`: образец и колода по пределам
экспортируются у каждого корпоративного шаблона с `pptx`, у остальных тест
пропускается. Правило 7 уже покрывает существующий тест полного контракта.

**Ручная приёмка.** В окружении разработки нет ни PowerPoint, ни LibreOffice,
поэтому автотесты не доказывают, что PowerPoint откроет файл без предложения
восстановить его. Один раз вручную на образце Lemana Tech в PowerPoint:

- файл открывается без восстановления;
- текст стоит в зонах мастера;
- «Изменить данные» у графиков работает;
- заметки на месте.

Кнопки интерфейса проверяются в браузере: `test_pages.py` проверяет только
отдачу страниц.

## 10. Выкатка и откат

1. **Продукт.** Зависимость `python-pptx` (тянет lxml, Pillow, XlsxWriter),
   `uv.lock`, код и тесты. Ни у одного шаблона ещё нет `pptx`, поэтому кнопка
   нигде не появляется — выкатка безопасна.
2. **Канон Lemana Tech.** Коммит в его репозиторий: `typst-deck/pptx.json` и
   поле `"pptx"` в `template.json`. Перед коммитом —
   `python -m typst_deck.templates <канон>` без ошибок.
3. **Сервер.** Обновить канон в точке монтирования и перезапустить сервис: поле
   `pptx` реестр увидит и так, а стартовая проверка правила 7 — только при
   старте.
4. **Ручная приёмка** (§9).

**Откат:** убрать поле `pptx` из канона — кнопка исчезнет. Откат продукта данных
не трогает: колоды и `build/` экспорт не меняет.

## 12. Риски

- **PowerPoint предлагает восстановить файл.** Причиной может стать удаление
  слайдов и заполнителей или добавленный номер слайда. Автотесты этого не
  ловят — закрывает ручная приёмка; при сбое первым делом сравнить XML с файлом,
  который PowerPoint пересохранил.
- **Вид отличается от PDF:** шрифты темы мастера, оформление титульного и
  заключительного слайдов из мастера. Принято решением «как в мастере».
- **Длинный заголовок вылезает из заполнителя** до первой правки. Держат пределы
  слотов; если на практике не хватит — отдельной задачей подбирать кегль.
- **Хозяин канона переименует макет.** Стартовая проверка выключит PPTX у
  шаблона с причиной в `/api/health`, а запрос получит 422 — тихой поломки нет.
- **Время сборки.** Мастер 2 МБ читается на каждый запрос. Замерить на колоде из
  20 слайдов; кэш — только если выйдет заметно дольше секунды.
- **Рост образа** из-за lxml и Pillow — оценка, замерить при сборке.
