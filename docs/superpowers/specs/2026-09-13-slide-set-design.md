# Набор слайдов и их контракты — проектная спецификация

Дата: 2026-09-13. Статус: **на ревью**.

## 1. Цель и границы

Сейчас колода знает шесть типов слайдов: `title`, `section`, `image`,
`bar-chart`, `chart`, `final`. Этого мало: в правилах дизайна Lemana Tech
описано десять типов, в её PowerPoint-мастере есть неиспользуемые макеты
«Блоки текста», «Таблица», «Акцентный» и «Статистика», а в Typst-каноне —
функции для повестки, двух колонок, метрик и сравнения. Из-за бедного набора
модель кладёт в `image` всё подряд: на проде все девять слайдов `image` — без
картинки.

**Задача:** пересобрать набор типов до пятнадцати, задать им контракт, перенести
существующие колоды и научить всему этому рендер, экспорт в PPTX, интерфейс и
модель.

**В границы входит:**

- 15 типов слайдов в `model.py`, их поля и глобальные пределы;
- разовая команда переноса сохранённых колод, версий и корзины;
- контракт `deck.typ`: 16 функций, маркеры полей, вложенные пределы слотов;
- шаблоны `default` и `dark`, реализующие все типы;
- экспорт в PPTX для всех типов и расширение `pptx.json`;
- интерфейс: меню типов, редакторы составных полей, загрузка видео, выдача
  файлов колоды, плеер;
- схема и памятка для модели;
- перевод канона Lemana Tech и выкатка одним окном.

**В границы не входит:**

- файл оформления шаблона (шрифты, кегли, цвета, графика) — подпроект 2;
  до него новые ключи оформления живут в `pptx.json`;
- новые шаблоны, в том числе стиль «как оформляет Claude», — подпроект 3;
- извлечение кадра из видео (ffmpeg в образе нет): обложка — загруженная
  картинка или заглушка шаблона;
- видео в PDF: PDF получает обложку со ссылкой, встроенного проигрывания нет.

## 2. Решения из обсуждения

| вопрос | решение |
|---|---|
| какие типы добавить | все восемь предложенных: повестка, блоки текста, цитата, сравнение, метрики, таблица, видео, два графика и галерея |
| кто их рисует | каждый шаблон реализует все типы сам; продукт базовой реализации не даёт |
| старые типы | пересобрать: `image` без картинки → `text`, `bar-chart` и `chart` → один `chart` с видом |
| перенос данных | разовая команда, модель принимает только новые типы |
| источник видео | файл в колоде (mp4 до 200 МБ) или внешняя ссылка |

Шаблон вправе импортировать эталонные функции и переопределить часть: проверено
2026-09-13, что в Typst имя из второго импорта перекрывает то же имя из первого.
Контракт это не ослабляет — шаблон всё равно экспортирует все функции.

## 3. Что установлено

**По коду (проверено 2026-09-11…13):**

- Маркер поля — `field(slide, name, body)` в `typst/fields.typ`: пишет в
  метаданные положение и размер, сервис читает их через `typst eval query(<edit>)`.
  Фронт рисует по кликабельной зоне на каждую запись позиций, поэтому у одного
  поля может быть несколько зон.
- Панель свойств умеет строки, списки строк (`bullets`, `labels`) и две таблицы:
  `data` и `series`. Массивов объектов в общем виде она не знает.
- `slots.py` различает три вида полей (строка, список строк, список прочего) и
  три ключа (`max`, `lines`, `count`); вложенных путей нет.
- Загрузка принимает только `.png`, `.jpg`, `.jpeg`, `.svg` и документы;
  `ingest_file` держит общий лимит `max_upload_mb` = 20 и читает файл в память.
- Эндпоинта выдачи файлов колоды нет: есть только `POST …/assets`.
- В nginx у `location /deck/` стоит `client_max_body_size 25m`.
- Версии лежат полными снимками в `versions/NNNNNN.json`, откат берёт из снимка
  `title` и `slides`. В корзине `data/trash/` пять удалённых колод той же
  структуры. В чате слайдов нет, только имена инструментов.
- На проде две колоды и шесть версий: 2 `title`, 9 `image` (все без картинки),
  4 `bar-chart`, 2 `chart`, 2 `final`; загруженных картинок нет.
- `SAMPLE_DECK` из `contract.py` служит и образцом контракта, и превью шаблона.

**По мастеру Lemana Tech** (геометрия в мм):

| макет | содержимое |
|---|---|
| Блоки текста | title (0) x83 y54; три заполнителя idx 10/11/12 — x83/249/415, y164, 150×129; декоративная полоса слева x0 w48 |
| Таблица | title (0) x83 y52 272×33 (левые 60 %); полоса слева x0 w50 |
| Акцентный | заполнителей нет; декоративные полосы сверху до y≈71 и снизу от y≈311 |
| Статистика | title (0) x83 y54 564×34; три шеврона на полосе y89–330 через всю ширину |

**По python-pptx:** `shapes.add_movie(file, …, poster_frame_image=…, mime_type=…)`
встраивает видео, `shape.click_action.hyperlink` ставит ссылку.

## 4. Каталог типов

| тип | назначение | поля |
|---|---|---|
| `title` | титул | title, subtitle, author, department |
| `agenda` | повестка | title, items |
| `section` | раздел | title, subtitle |
| `text` | заголовок и тезисы | title, bullets |
| `image` | текст и картинка | title, bullets, image, image_size, caption |
| `columns` | блоки текста | title, blocks: (heading, text) |
| `comparison` | сравнение | title, left и right: (heading, bullets) |
| `quote` | акцент, цитата | text, author |
| `chart` | график | title, kind, labels, series, unit, bullets |
| `dual-chart` | два графика | title, left и right: (caption, kind, labels, series, unit) |
| `metrics` | крупные числа | title, items: (value, label, delta) |
| `table` | таблица | title, header, rows |
| `gallery` | 2–4 картинки | title, images: (image, caption) |
| `video` | видео | title, video, url, poster, caption |
| `final` | финал | title, contact |

У всех типов, как и раньше, есть `id` и `notes`.

**Глобальные пределы.** Объявление шаблона может их только сузить.

| тип | пределы |
|---|---|
| `agenda` | items 3–7, до 80 знаков |
| `text` | bullets 1–6 по 200 |
| `image` | bullets 0–6 по 200; при `image_size` `large` — суммарно не больше 900 знаков; `image` обязательна |
| `columns` | blocks 2–3; heading до 60, text до 300 |
| `comparison` | heading до 60; bullets 1–5 по 120 с каждой стороны |
| `quote` | text до 300, author до 120 |
| `chart` | kind `bar` или `line`; labels: bar от 1, line от 2, до 24; series 1–4; bullets 0–4 по 120 |
| `dual-chart` | на график: caption до 80, labels до 12, series 1–3 |
| `metrics` | items 2–4; value до 16, label до 60, delta до 12 |
| `table` | header 2–6 по 40; rows 1–8; в строке столько же ячеек, сколько в шапке; ячейка до 40 |
| `gallery` | images 2–4; caption до 80 |
| `video` | ровно одно из `video` (ассет `.mp4`) и `url`; poster необязателен; caption до 120 |

Заголовки — прежние 120 знаков. `delta` — строка со знаком («+12 %»).

**Три предела сняты замером, а не назначены** (2026-09-14, оба эталонных шаблона,
граница содержимого страницы 232.44 пт). Прежние обещали объём, который не влезает
ни при каком читаемом кегле — вёрстка упиралась в пол лестницы кеглей 4pt:

| поле | было | стало | что мерили |
|---|---|---|---|
| `chart.bullets` | 4 × 200 | 4 × 120 | колонка выводов 124×76.7 пт: 4×150 уходят под обрез на 3.80 пт |
| ячейка `table` | 60 | 40 | 8 строк × 6 ячеек: 44 знака уходят на 15.52 пт |
| `image` при `image_size: large` | 6 × 200 | сумма ≤ 900 | крупная картинка берёт 55 % ширины: 6×200 уходят на 18.38 пт, 6×150 влезают |

Предел у `large` — перекрёстный (`model_validator`), а не в самом поле: при
`medium` и `small` те же 6 × 200 помещаются, и резать их глобально значило бы
наказать тех, кто крупную картинку не выбирал.

## 5. Перенос

Разовая команда `python -m typst_deck.migrate_slides` по образцу
`migrate_template`: модель после неё принимает только новые типы.

| было | стало |
|---|---|
| `title`, `section`, `final` | без изменений |
| `image` с картинкой | `image` |
| `image` без картинки | `text` (title, bullets, notes); `caption` без картинки не рисовалась и отбрасывается |
| `bar-chart` | `chart` kind `bar`: labels из `data[].label`, одна серия с именем `unit` или «Значение» и значениями `data[].value` |
| `chart` | `chart` kind `line` |

Свойства команды:

- переписывает `deck.json` и все снимки `versions/` в `decks/` и в `trash/`;
- `id` слайдов сохраняет, версию не поднимает: это смена формата, а не правка;
- идемпотентна: новые слайды не трогает;
- `--check` печатает, что изменится, ничего не записывая;
- каждую колоду перед записью проверяет новой моделью и пишет все её файлы
  целиком или ни одного.

Чат и позиции не трогаются, кэш `template-previews/` очищается.

## 6. Контракт шаблона

`deck.typ` экспортирует `deck` и 15 функций слайдов.

```typst
#let slide-title(title: none, subtitle: none, author: none, department: none)
#let slide-agenda(title: none, items: ())
#let slide-section(title: none, subtitle: none)
#let slide-text(title: none, bullets: none)
#let slide-image(title: none, bullets: none, image: none, image-size: "medium", caption: none)
#let slide-columns(title: none, blocks: ())
#let slide-comparison(title: none, left: (:), right: (:))
#let slide-quote(text: none, author: none)
#let slide-chart(title: none, kind: "line", labels: (), series: (), unit: none, bullets: none)
#let slide-dual-chart(title: none, left: (:), right: (:))
#let slide-metrics(title: none, items: ())
#let slide-table(title: none, header: (), rows: (), numeric: ())
#let slide-gallery(title: none, images: ())
#let slide-video(title: none, poster: none, url: none, caption: none)
#let slide-final(title: none, contact: none)
```

Правила прежние: текстовые значения приходят как content, уже обёрнутый в маркер
поля; `labels`, `series`, `numeric` и числа — сырые массивы; одна функция —
ровно одна страница; переполнение обрезается.

**Составные поля.** Каждую текстовую часть продукт оборачивает маркером с именем
поля верхнего уровня (`field(id, "blocks", …)`), поэтому у поля бывает несколько
зон, и любая открывает редактор всего поля. Правка по-прежнему заменяет поле
верхнего уровня целиком.

**Что продукт вычисляет за шаблон:**

- `trend` у метрики — по знаку в начале `delta`: `+` — рост, `-` или `−` —
  падение, иначе `none`; шаблон только красит;
- `numeric` у таблицы — колонки, где все ячейки читаются как числа (с пробелами,
  `%` и единицей); шаблон выравнивает их вправо;
- `url` у видео — внешняя ссылка или ссылка на файл колоды через
  `GET /api/decks/{id}/assets/{asset}`; если `poster` нет, заглушку рисует шаблон.

**Слоты.** Объявление получает пути с точкой для вложенных полей:

```json
"columns": {"blocks": {"count": 3}, "blocks.text": {"max": 180}}
```

`measure_slots.py` учится мерить такие поля по зонам из `measure.json`.

**Проверка.** Правила остаются семью. Образец получает слайд каждого типа, и
страниц в нём становится 15. Поскольку `image` и `gallery` требуют картинку,
проверка и построение превью кладут рядом с образцом одну-две крошечные PNG.
Правило 3 добавляет к перебору цитату, блоки, метрики и ячейки таблицы, правило
4 требует маркер у каждого нового текстового поля, правило 5 собирает слайды по
вложенным пределам.

## 7. Экспорт в PPTX

`pptx.json` описывает все 15 типов тем же способом: макет, заполнители `ph`,
зона `body`, параметры.

| тип | в `ph` обязательно | `body` | параметры |
|---|---|---|---|
| title, section, final | как сейчас | — | — |
| agenda, text, table, video | title | да | — |
| image | title | да | image_width, gap |
| columns | title и `blocks: [idx, …]`, либо зона | если нет `blocks` | gap при зоне |
| comparison, dual-chart, metrics, gallery | title | да | gap |
| quote | ничего | да | — |
| chart | title | да | text_width, gap, heading |

Как рисуется:

- **agenda** — нумерованный список средствами PowerPoint, номер цвета маркера;
- **columns** — жирный заголовок блока, затем текст; лишние заполнители удаляются;
- **comparison** — две колонки: жирный заголовок и тезисы;
- **quote** — текст по центру зоны по обеим осям, автор ниже цветом подписи;
- **metrics** — равные колонки: крупное число, подпись, изменение цветом тренда;
- **table** — нативная таблица: жирная шапка на заливке, «зебра», тонкие линии,
  числовые колонки вправо;
- **chart** — одна серия красится по знаку, несколько — по палитре;
- **dual-chart** — два нативных графика, над каждым подпись;
- **gallery** — 2 в ряд, 3 в ряд, 4 сеткой 2×2, каждая вписана, под ней подпись;
- **video** — встроенный ролик с обложкой, если файл; обложка с гиперссылкой и
  подписью, если ссылка; заглушку обложки рисует Pillow цветами сопоставления.

## 8. Интерфейс и модель

**Интерфейс:**

- меню «Добавить слайд» — все 15 типов с русскими названиями и заготовками;
- один общий табличный редактор для массивов объектов (блоки, метрики, картинки
  галереи) со строками в пределах лимитов; `comparison` и `dual-chart` — две
  фиксированные группы; `table` — сетка шапки и строк; `chart` — выбор вида,
  подписи и нынешний редактор рядов (отдельная таблица `data` уходит вместе с
  `bar-chart`); `video` — загрузка mp4 или ссылка, обложка, подпись; `quote` —
  текст и автор;
- клик по любой зоне составного поля открывает вкладку «Слайд» на редакторе
  этого поля; всплывающий редактор остаётся для простого текста;
- на слайде с видео поверх сцены — кнопка «▶ Смотреть»: загруженный ролик
  играет в плеере, ссылка открывается в новой вкладке.

**Файлы:**

- `POST …/assets` и загрузка из чата принимают `.mp4` до 200 МБ и пишут файл
  потоком, а не в память; в чате ролик становится ассетом;
- новый `GET /api/decks/{id}/assets/{asset}` отдаёт файлы колоды — нужен для
  ссылки из PDF и для плеера; поддержка `Range` проверяется при реализации;
- агентское API видео не принимает (base64 в JSON), бот может дать ссылку;
- в `~/stack/nginx/portfolio.conf` лимит `location /deck/` поднимается с 25m
  до 210m.

**Модель:** схема строится из `model.py`, как сейчас. В `prompt.md` появляется
памятка, какой тип когда брать: `title` первым и `final` последним; `agenda`
вторым при трёх и более разделах; `text` — тезисы, `image` — только при
подходящей картинке; `columns` — 2–3 равных по объёму пункта; `comparison` —
«было/стало»; `quote` — одна мысль не чаще раза на 5–7 слайдов; `chart` `bar` —
сравнение категорий, `line` — динамика; `dual-chart` — два связанных графика;
`metrics` — 2–4 ключевых числа; `table` — точные значения; `gallery` — 2–4
картинки; `video` — только если ролик или ссылку дал пользователь. Числа — только
из файлов пользователя. Список ассетов в промпте делится на картинки и видео.
Инструменты модели не меняются.

## 9. Тесты

- **Модель и перенос:** типы и пределы; длина строки таблицы равна шапке; у видео
  ровно одно из файла и ссылки; конвертер старых слайдов, повторный запуск,
  атомарность по колоде, корзина и снимки версий, режим `--check`.
- **Слоты:** пути с точкой в объявлении, схеме и проверке; замер таких полей.
- **Рендер:** образец из 15 типов на `default` и `dark` — одна страница на слайд,
  маркеры на месте, переросший текст не ломает страницу.
- **PPTX:** по тесту на тип на синтетическом мастере — заполнители и зоны,
  нативная таблица, встроенное видео, обложка со ссылкой, заглушка обложки, сетка
  галереи; проверка новых ключей сопоставления.
- **API:** выдача файла колоды и перемотка, загрузка mp4 и лимит, экспорт колоды
  с видео.
- **Страницы:** новые элементы панели и кнопка плеера присутствуют.
- **Корпоративные:** Lemana собирает все 15 типов по одной странице, экспортирует
  их в PPTX, объявленные пределы влезают в зоны.

**Ручная приёмка:** PPTX с таблицей, видео и галереей открывается в PowerPoint
без предложения восстановить файл; видео проигрывается; ссылка на внешнее видео
открывается.

**Проверка вёрстки — картинкой и измерением.** Тесты держат контракт: каждый тип
рисуется и даёт ровно одну страницу. Качество вёрстки они не видят — в плане A
так нашлись потерянные данные у многорядной гистограммы, обрезанные подписи
категорий и неразличимая палитра тёмного шаблона. Поэтому задача, которая трогает
вёрстку, заканчивается рендером оговорённого списка случаев (содержимое на
пределах модели: 7 пунктов повестки, 5 тезисов на сторону сравнения, 6 тезисов
текстового слайда, 4 колонки метрик, 3 ряда на сторону у двух графиков) на обоих
шаблонах.

При этом картинка даёт только гипотезу. Обрезку и наложение подтверждают
измерением: `typst eval 'query(<edit>)'` отдаёт положение и высоту каждого поля,
и низ поля сравнивается с нижней границей содержимого страницы. В плане A
проверка глазами трижды дала ложную тревогу — нижние пиксели последней строки
теряются при растеризации, — и стоила лишнего раунда правок.

## 10. Порядок работ и выкатка

Четыре плана на одной ветке `slides-v2`:

| план | что делает | зависит от |
|---|---|---|
| A. Ядро | 15 типов, перенос, контракт Typst и маркеры, слоты с путями, образец и правила, `default` и `dark`, схема и памятка | — |
| B. PPTX | экспорт всех типов, новые ключи сопоставления, таблица, видео, галерея | A |
| C. Интерфейс | панель и редакторы, меню типов, загрузка mp4, выдача файлов, плеер, лимит nginx | A |
| D. Канон | адаптер Lemana, `pptx.json`, замер слотов, корпоративные тесты | A, B, C |

В `main` промежуточные состояния не сливаются: выкаченный новый продукт со
старым каноном сломал бы Lemana Tech.

**Выкатка одним окном** (канон смонтирован в сервис живым каталогом):

1. правка канона готовится в его git worktree и проверяется на сервере
   разработки новым продуктом;
2. `podman volume export typst-deck-data` — резервная копия;
3. остановка сервиса;
4. канон вливается перемоткой вперёд;
5. `python -m typst_deck.migrate_slides` — перенос колод;
6. новый образ (метка отката на прежний) и запуск;
7. правка nginx стека и его перезагрузка;
8. проверки на живом сервисе и ручная приёмка.

**Откат:** вернуть канон на прежний коммит, восстановить том из копии, вернуть
метку образа, запустить. Правки колод после выкатки при откате пропадут.

## 11. Риски

- **Объём:** примерно вчетверо больше работы по экспорту в PPTX; отсюда четыре
  плана.
- **Промпт растёт:** схема 15 типов увеличивает системный промпт. Замерить его
  размер до и после и при необходимости сократить описания полей.
- **Шаблоны дорожают:** каждый новый шаблон — 16 функций. Частично лечится
  импортом эталона с переопределением.
- **Видео на 200 МБ:** запись потоком, лимит nginx, время ответа, место в томе.
  Размер тома проверить до выкатки.
- **Мастера без нужных макетов:** у шаблона может не быть подходящего макета под
  тип; тогда тип ложится на «Стандартный» с зоной, и это решение автора шаблона.
