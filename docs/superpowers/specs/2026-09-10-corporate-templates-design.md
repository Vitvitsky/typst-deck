# Корпоративные шаблоны вне продукта и контракт шаблона — проектная спецификация

Дата: 2026-09-10. Статус: **принято к реализации**.

## 1. Цель и границы

typst-deck — продукт, который рендерит презентации по шаблону. Корпоративный
шаблон Lemana Tech сейчас живёт внутри продукта: адаптер в `templates/lmru-hr/`,
а канон копируется туда скриптом `scripts/sync-lmru-template.sh` из соседнего
репозитория. У компании несколько юрлиц, и скоро понадобится второй шаблон —
LemanaPro — со своим каноном в отдельном репозитории.

**Задача:** вынести корпоративные шаблоны из продукта так, чтобы владелец
канона сам делал его совместимым с typst-deck, а typst-deck подключал его
настройкой, без правок кода. Для этого контракт шаблона становится отдельной
инструкцией с проверкой, которой можно прогнать любой шаблон.

**В границы входит:**

- документ `docs/template-contract.md` и проверка шаблона на соответствие ему;
- поле `fonts` в `template.json`;
- перенос Lemana Tech в его репозиторий канона и переименование id
  `lmru-hr` → `lemana-tech`;
- алиасы старых id и перенос двух боевых колод на новый id;
- проверка подключённых шаблонов при старте сервиса;
- монтирование канона в боевой контейнер.

**В границы не входит:**

- сам шаблон LemanaPro: репозитория его канона ещё нет, он делается по
  контракту из этой спеки отдельной задачей;
- переименование каталога канона на диске: id задаётся точкой монтирования,
  а не именем каталога.

## 2. Что установлено по коду

Проверено 2026-09-10.

- **Несколько корней шаблонов уже поддержаны.** `TYPST_DECK_TEMPLATES_DIR`
  принимает корни через `:`, при совпадении id побеждает первый
  (`templates.py`). Механизм задумывался ровно для закрытого каталога,
  примонтированного в контейнер.
- **Песочница typst не выходит за корень шаблона.** Корень сборки — каталог
  `build/` колоды, шаблон виден в нём как ссылка `build/template`. Всё, что
  шаблон импортирует и рисует, обязано лежать внутри его каталога.
- **Канон Lemana Tech уже разрешает компоненты изнутри своего репозитория:**
  `lm-components-dir = "../../references/components"` считается от
  `templates/typst/`. Если корень шаблона — корень репозитория канона, канон
  работает без перекладывания файлов.
- **Канон запрашивает несуществующее семейство шрифта.** Он просит
  `"TT Interphases Pro Trl"` (имя пробной версии), а TTF в его же
  `references/TTInterphasesPro.zip` называются `"TT Interphases Pro"`. Любой
  потребитель с настоящим шрифтом молча получает Liberation Sans. Скрипт
  синхронизации латал это на копии.
- **Шрифты канона лежат только в zip,** а typst читает каталог файлов.
- **Путь к шрифтам зашит:** `compile_deck` берёт `<шаблон>/fonts`,
  `compile_pdf` — `build/template/fonts` (`render.py`).
- **Образ несёт корпоративный канон.** `Dockerfile` копирует `templates/`
  целиком, поэтому README запрещает публиковать образ. Проверка «каждый шаблон
  собирает образец» идёт при сборке образа (`RUN python -m typst_deck.templates`)
  и смонтированные шаблоны не увидит.
- **Id шаблона хранится в данных.** Две боевые колоды записаны с
  `template: "lmru-hr"`. Агентское API принимает `template` параметром
  (`api/agent.py`), так что бот мог где-то зафиксировать старый id.
- **Откат колоды не трогает шаблон:** `POST …/revert` копирует из снимка только
  `title` и `slides`. Старый id в снимках `versions/` безвреден.
- **Геометрия слотов для замера зашита в продукте:** `PROBES` в
  `scripts/measure_slots.py` под ключом `"lmru-hr"`, а пробный `.typ`
  импортирует `slides_template.typ` по имени.

  `lemana-tech → ~/projects/lmru--hr-analytics--design-template`;

  локально: в контейнер шаблон попадает монтированием.

LemanaPro позже встаёт так же: свой репозиторий, свой `Volume=…:/corp/lemana-pro:ro`.

## 4. Контракт шаблона

`docs/template-contract.md` — инструкция для автора шаблона. Эталон —
`template/deck.typ`, на него контракт ссылается в каждом пункте.

**Корень.** Шаблон — каталог. Всё, что он использует (импорты, картинки,
шрифты), лежит внутри. Ссылки, выводящие за корень, запрещены: локально
работают, в контейнере рвутся.

**Обязательные файлы в корне:**

- `deck.typ` — экспортирует функции:
  ```typst
  #let deck(title: none, body)
  #let slide-title(title: none, subtitle: none, author: none, department: none)
  #let slide-section(title: none, subtitle: none)
  #let slide-image(title: none, bullets: none, image: none, image-size: "medium", caption: none)
  #let slide-bar-chart(title: none, data: (), unit: none, bullets: none)
  #let slide-chart(title: none, labels: (), series: (), unit: none, bullets: none)
  #let slide-final(title: none, contact: none)
  ```
- `template.json`:
  | поле | обязательно | смысл |
  |---|---|---|
  | `name` | да | имя в интерфейсе |
  | `description` | нет | подпись в «Моих шаблонах» |
  | `fonts` | нет | каталог шрифтов от корня; по умолчанию `fonts` |
  | `measure` | нет | файл геометрии слотов для замера |
  | `slots` | нет | ёмкость слотов (см. спеку ёмкости) |

**Параметры.** Текстовые (`title`, `subtitle`, `author`, `department`,
`caption`, `contact`, `bullets`) приходят как content, уже обёрнутый в маркер
поля, или `none`; строковых операций над ними не делать. `bullets` — готовый
список. `image` — content или `none`. `data`, `labels`, `series` — сырые
массивы и словари, графики шаблон рисует сам. Пакеты `@preview` не
использовать: у корпоративной сети может не быть доступа к реестру.

**Одна функция — ровно одна страница.** Переполнение обрезается
(`box(clip: true)`), а не переносится на следующую страницу: сервис
сверяет число страниц с числом слайдов.

**Шрифты.** Файлы TTF/OTF в каталоге `fonts`. Семейства, которые называет
`deck.typ`, обязаны совпадать с семействами внутри файлов.

**Ёмкость.** Раздел `slots` объявляет пределы, измеренные
`scripts/measure_slots.py` по геометрии из файла `measure`. Автоподбор кегля
(приём `fit-text` из эталона) — рекомендация для зон заголовков.

**Проверка:**
`uv run --project ~/projects/typst-deck python -m typst_deck.templates <каталог шаблона>`
прогоняет правила контракта и печатает нарушения. Без аргумента, как сейчас,
проверяет все шаблоны реестра.

Правила проверки:

1. есть `deck.typ` и `template.json`, `template.json` читается, `slots`
   проходят `clamp` без единого предупреждения;
2. образец (по слайду каждого типа) собирается, страниц столько же, сколько
   слайдов;
3. переросший вход — текст предельной длины и много переводов строки в
   title, section и final — даёт одну страницу;
4. у каждого текстового поля образца есть маркер `<edit>`: без него не
   работает правка по клику;
5. слайд, заполненный ровно по объявленным пределам, собирается в одну
   страницу;
6. typst не сообщает `unknown font family`: такое предупреждение считается
   ошибкой, это ровно тот случай, из-за которого канон молча получал чужой
   шрифт.

## 5. Перенос Lemana Tech

**В репозитории канона** (свои коммиты там; remote у репозитория нет):

- `typst-deck/adapter.typ` — нынешний `templates/lmru-hr/deck.typ`, импорт
  канона меняется на `../templates/typst/slides_template.typ`;
- `deck.typ` в корне — одна строка импорта адаптера;
- `typst-deck/fonts/` — TTF из `references/TTInterphasesPro.zip`;
- `typst-deck/measure.json` — геометрия из `PROBES`, строка импорта канона и
  оформление списка, которое сейчас скопировано в `measure_slots.py`;
- `template.json` в корне: `"name": "Lemana Tech"`, текущее описание,
  `"fonts": "typst-deck/fonts"`, `"measure": "typst-deck/measure.json"`,
  текущие измеренные `slots`;
- в `slides_template.typ` в списки шрифтов первым встаёт
  `"TT Interphases Pro"` — это лечит тихую подмену шрифта у всех
  потребителей канона, не только у typst-deck; строка про шрифт в `CLAUDE.md`
  канона правится следом, и там же появляется ссылка на контракт.

Каталог канона не переименовывается: id задаёт точка монтирования.

**В typst-deck:**

- удаляются `templates/lmru-hr/`, `scripts/sync-lmru-template.sh` и блок
  `.gitignore` про канон;
- реестр читает `fonts` и отдаёт абсолютный путь к шрифтам; его получают и
  `compile_deck`, и `compile_pdf`;
- `scripts/measure_slots.py` принимает путь к корню шаблона и читает
  геометрию из файла `measure`; `PROBES` из скрипта уходят;
- README: раздел про Lemana Tech заменяется подключением корпоративного
  шаблона через монтирование, запрет на публикацию образа снимается.

**Старый id.** `TYPST_DECK_TEMPLATE_ALIASES=lmru-hr:lemana-tech` (несколько
пар — через запятую: `старый:новый,старый2:новый2`) — реестр
разрешает старый id в новый при любом обращении: создание колоды, смена
шаблона, агентское API, рендер. В списке шаблонов виден только новый id.
Алиас задаётся окружением, а не кодом: история корпоративных id — дело
развёртывания, а не продукта. Снимается, когда бот гарантированно шлёт
новый id.

**Перенос колод.** Разовая команда
`python -m typst_deck.migrate_template lmru-hr lemana-tech` переписывает поле
`template` в `deck.json` через `write_atomic`, без подъёма версии: это
переименование, а не правка. Снимки `versions/` не трогаются (§2). Повторный
запуск ничего не меняет. Запускается при остановленном сервисе, чтобы не
гоняться с его записью, из того же образа и на том же томе:
`podman run --rm -v typst-deck-data:/data localhost/typst-deck:latest python -m typst_deck.migrate_template lmru-hr lemana-tech`.

## 6. Проверка шаблонов при старте

Смонтированные шаблоны при сборке образа не видны, поэтому сервис проверяет
их сам.

- При старте, в фоновом потоке, чтобы не задерживать запуск, каждый шаблон
  реестра собирает образец. Полный набор правил из §4 — для автора и CI:
  он дороже и строже, чем нужно работающему сервису.
- **Сломанным** шаблон считается, только если он не может работать: нет
  `deck.typ` или `template.json`, `template.json` не читается, образец не
  собирается или страниц не столько, сколько слайдов (правило 2). Такой шаблон
  скрыт из `/api/templates` и из списка шаблонов в промпте; создание колоды
  или переезд на него отвечают 422 с причиной; рендер колоды на нём сообщает
  причину вместо сырой ошибки typst.
- **Предупреждения** шаблон не ломают: `unknown font family` (правило 6) и
  отброшенные `clamp` ключи `slots`. Вёрстка с чужим шрифтом или без части
  пределов уродлива, но работает, а скрыть из-за неё шаблон значило бы
  остановить все колоды на нём. Предупреждения пишутся в лог и в
  `/api/health`.
- `/api/health` получает
  `"templates": {"ok": [...], "broken": {"<id>": "<причина>"}, "warnings": {"<id>": ["…"]}}`
  и продолжает отвечать `ok: true`. Иначе юнит с `Notify=healthy` не
  поднимется, и одна сломанная корпоративная вёрстка положит сервис для
  всех колод.
- Отсутствующий корень, например несмонтированный канон, реестр уже пишет
  в лог; колоды на таком шаблоне получают «шаблон не найден».

## 7. Тесты

- **Реестр:** `fonts` из `template.json` доезжает до обеих компиляций;
  алиасы из окружения разрешаются в `get`, `dir_for` и при создании колоды,
  в списке только новые id; сломанный шаблон скрыт и отвечает 422 с причиной.
- **Проверка контракта:** `default` и `dark` проходят все шесть правил; для
  каждого правила есть намеренно сломанный шаблон-образец в `tests/fixtures/`,
  и проверка называет именно это нарушение.
- **Перенос колод:** id переписывается, версия не растёт, повторный запуск
  ничего не меняет, колоды на других шаблонах не тронуты.
- **Корпоративный набор:** тесты, которые сейчас завязаны на
  `templates/lmru-hr` (инцидент 2026-09-09, ёмкость `bar-chart`, пределы
  помещаются в вёрстку, длинный заголовок в слоте, цвета графиков),
  становятся общими и параметризуются по корпоративным шаблонам из
  `TYPST_DECK_TEST_TEMPLATES` — в том же формате, что
  `TYPST_DECK_TEMPLATES_DIR` (корни через `:`; корпоративными считаются все
  шаблоны этих корней). Без переменной они пропускаются с внятной причиной;
  на этом сервере она указывает на `~/corp-templates`.
- **Тесты агента,** где `lmru-hr` — просто строка-id, берут нейтральный id и
  канона не требуют.

## 8. Выкатка и откат

1. Коммиты в каноне (§5), проверка `python -m typst_deck.templates <канон>`.
2. Слияние typst-deck.
3. Сборка образа; `systemctl --user stop typst-deck`; перенос колод
   командой из §5, запущенной из нового образа на томе `typst-deck-data`.
4. Юнит `~/stack/quadlet/typst-deck.container`: `Volume=` канона,
   `TYPST_DECK_TEMPLATES_DIR`, `TYPST_DECK_TEMPLATE_ALIASES`; копия в
   `~/.config/containers/systemd/`, `daemon-reload`, `start`.
5. Проверка: `/api/templates` показывает `lemana-tech`, обе колоды собираются,
   в `/api/health` нет сломанных шаблонов.
6. Документация стека: монтирование канона в `~/stack/quadlet/README.md`.

**Откат:** прежний образ и прежний юнит; колоды возвращаются той же командой
с обратными аргументами.

## 10. Риски

- **Канон знает о typst-deck.** Папка `typst-deck/` и два файла в корне
  появляются в чужом по назначению репозитории. Цена принята: правка канона
  и адаптера — один коммит, копирование и `CANON_REV` исчезают.
- **Весь репозиторий канона монтируется в контейнер** — 15 МБ вместе с pptx и
  скриншотами, только на чтение. Typst ничего не пишет в каталог шаблона:
  сборка идёт в каталог колоды.
- **Адаптер опирается на внутренности канона** (`title-slide`, `content-slide`,
  их параметры). Так было и раньше, но теперь поломка видна в том же
  репозитории, где её вызвали, и её ловит проверка из §4.
- **Бот мог зафиксировать `lmru-hr`.** Алиас закрывает это до явного
  подтверждения; без него создание колоды со старым id ответило бы 422.
- **Rootless podman и права.** Контейнер работает от root внутри, что в
  rootless-режиме отображается на владельца `~/projects`, так что чтение
  канона не упрётся в права. Если в образе появится `USER`, монтированию
  понадобится `--userns=keep-id`.
