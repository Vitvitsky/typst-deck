# typst-deck — клиентские пути, требования, ресерч

Дата: 2026-09-08. Основание: скриншоты текущего интерфейса (главная и
страница колоды на 1366×850), реальная колода «ИИ-платформа» из 15 слайдов,
обзор Gamma, Beautiful.ai, Pitch, Copilot Narrative Builder, typst.app и
паттернов AI-loading-states.

## 1. Кто пользуется

- **Сотрудник без навыков вёрстки** (основной). Приходит с Word/Excel и
  задачей «нужна презентация к среде». Не знает слов «шаблон», «слайд типа
  image», «патч». Хочет результат в корпоративном стиле и возможность быстро
  подправить текст руками.
- **Пользователь корпоративного чат-бота**. Просит презентацию в чате,
  получает PDF и ссылку. Попадает на страницу колоды впервые и без контекста.
- **Владелец шаблона/сервиса** (редко). Смотрит, что модель делает не так,
  откатывает версии, читает предупреждения рендера.

## 2. Клиентские пути

Формат: шаги → что должен видеть человек → где сейчас больно.

### J1. Создать презентацию из материалов

1. Открыл `/deck/` → сразу понятно, что здесь делают и с чего начать.
2. Описал задачу, перетащил файлы → видит список файлов с размером и типом,
   может убрать лишний.
3. Нажал «Создать» → попадает на страницу колоды, где идёт сборка: понятно,
   что происходит (читаю файлы → модель собирает структуру → верстаю), сколько
   прошло времени, что можно делать (ждать, вернуться в каталог).
4. Слайды появились → первое, что видно: обзор всей колоды, а не один слайд
   на весь экран; ответ модели с итогом; подсказка, как править.

Сейчас: форма без примеров и без дропзоны (нативный `Choose Files`), после
создания страница колоды показывает пустоту и крутящийся баннер без стадий;
после сборки виден один слайд на весь экран.

### J2. Быстро поправить руками

1. Заметил ошибку в заголовке → наводит на слайд и **видит**, что поля
   кликабельны (сейчас зоны невидимы до наведения точно на текст).
2. Кликнул → редактор поля рядом, Enter сохраняет, Esc отменяет.
3. Хочет заменить картинку → на слайде понятно, где картинка и как её
   загрузить; для слайда без картинки понятно, как добавить.
4. Хочет всё поле слайда сразу → панель свойств выбранного слайда, не
   всплывашка поверх страницы.
5. Ошибся → «Отменить» на одно действие или история версий.

Сейчас: панель всех полей рендерит `data`/`series` как сырой JSON; нет
выделения текущего слайда; нет быстрой отмены (только список версий).

### J3. Доработать через чат

1. Пишет «на 8 слайде добавь картинку с котиком» → модель отвечает, что
   картинок нет и просит загрузить → **должна быть кнопка загрузки прямо в
   чате**, иначе тупик (реальный кейс из сегодняшней колоды).
2. Пишет «короче заголовки во втором разделе» → пока модель работает, видно
   состояние; по завершении подсвечены изменённые слайды, в чате перечислено,
   что поменялось, есть «Откатить эту правку».
3. Не знает, что просить → подсказки-чипы рядом с полем ввода
   («Сократи текст», «Добавь слайд с выводами», «Разбей на разделы»).

Сейчас: вложений в чате нет; изменённые слайды не подсвечиваются; пустой
ответ показывался пустым пузырём; ops выводятся как `update_slide s5`
(внутренние идентификаторы).

### J4. Вернуться к колоде позже / найти чужую

1. Открыл `/deck/` → каталог с обложками, названием, датой, числом слайдов,
   состоянием (собирается / готова / ошибка).
2. Ищет свою среди многих → поиск по названию, сортировка по дате.
3. Не нужна → удалить с подтверждением (в корзину, не безвозвратно).

Сейчас: каталог есть (сделан сегодня), нет поиска и удаления.

### J5. Забрать результат

1. «Скачать PDF» заметна и доступна с любого экрана колоды.
2. Понятно имя файла (название колоды), понятно, что PDF соответствует
   текущей версии.
3. Ссылка на колоду копируется одной кнопкой (для чата/почты).

### J6. Пришёл из чат-бота по ссылке

1. Открыл `edit_url` → видит название, слайды и **исходный запрос бота в
   чате** как первое сообщение, чтобы понимать контекст.
2. Дальше как J2/J3.

### J7. Что-то пошло не так

- LLM недоступна → на главной сразу баннер «Генерация недоступна: не
  настроен ключ», ручная правка работает.
- Обрезка ответа по лимиту → сообщение с причиной и кнопкой «Повторить».
- Шаблон не собрался → предупреждение с текстом ошибки рендера, колода
  откатывается на прошлую версию автоматически (уже так), человеку об этом
  сказано.
- Картинка не найдена → жёлтая полоса над превью со ссылкой на слайд.

## 3. Требования

### Функциональные (нумерация для ссылок из плана)

- **R1** Каталог: обложка, название, число слайдов, дата, состояние; поиск
  по названию; удаление в корзину с подтверждением; свежие сверху.
- **R2** Создание: дропзона с перетаскиванием, список файлов с типом
  (текст/таблица/картинка) и размером, примеры запросов чипами, проверка
  пустой формы, предупреждение о неподдерживаемом формате до отправки.
- **R3** Страница колоды — три зоны: слева лента миниатюр (обзор и
  навигация), в центре слайды, справа чат и свойства выбранного слайда.
- **R4** Состояние генерации: стадии (файлы → модель → вёрстка), прошедшее
  время, отмена невозможна (честно сказать), скелетоны вместо пустоты.
- **R5** Правка на слайде: поля подсвечиваются при наведении на слайд;
  редактор поля с Enter/Esc; картинка — загрузка, замена, размер, удаление.
- **R6** Панель свойств выбранного слайда: все поля в человеческих формах
  (данные диаграммы — таблица label/value, серии — таблица), без JSON.
- **R7** Чат: вложения (картинки → ассеты, документы → материалы), чипы
  подсказок, ответ модели с перечислением изменённых слайдов по номеру и
  названию, кнопка «Откатить эту правку» у сообщения, ошибки с причиной и
  «Повторить».
- **R8** После правки модели изменённые слайды подсвечиваются в ленте.
- **R9** Кнопки колоды: скачать PDF, копировать ссылку, переименовать,
  история версий, вернуться в каталог.
- **R10** Ничего не открывается через `alert`/`confirm` браузера: тосты и
  встроенные подтверждения.

### Нефункциональные

- Работает под префиксом `/deck/` за Nginx (относительные пути).
- Без внешних шрифтов и CDN: корпоративная сеть может их не пропускать.
- Клавиатура: Tab по элементам, видимый фокус, Esc закрывает, Enter
  сохраняет однострочные поля.
- `prefers-reduced-motion` отключает анимации.
- Ширина от 1024px — полноценно; от 768 — две зоны (лента сворачивается);
  телефон — только просмотр и чат.
- Никаких внутренних идентификаторов в тексте интерфейса (`s5`,
  `update_slide`) — только номера и названия слайдов.

## 4. Ресерч: что взять, что не брать

**Gamma** (лидер сегмента). Поток: промпт → настройки (число карточек,
язык) → **редактируемый план** → тема → генерация 30–45 с → редактор блоков,
клик по элементу правит его на месте, «Edit with AI» на выделенном тексте,
персистентный агент в чате. Берём: план перед генерацией как опция (у нас
генерация занимает минуту, промах стоит дорого), клик-по-элементу,
агент в боковой панели. Не берём: свободные карточки вместо слайдов — у нас
фиксированный корпоративный шаблон, и это сознательное ограничение.

**Beautiful.ai / Pitch.** «Smart slides» с автоперекладкой и жёсткими
ограничениями макета как главная ценность: пользователь не может сломать
дизайн. Это ровно наша модель («править можно только параметры шаблона») —
значит, ограничение надо подавать как достоинство: «слайды всегда в
корпоративном стиле», а не как «нельзя».

**Copilot Narrative Builder.** Промпт + файл → структура тем → пользователь
удаляет/добавляет/переставляет темы, подкладывает документы к темам → только
потом слайды. Подтверждает ценность этапа плана. Берём как режим «Сначала
план» (флажок на форме создания), по умолчанию выключен: большинство хочет
сразу результат.

**typst.app / typst-preview.** Двухпанельный редактор с превью и переходом
из превью в исходник по клику. Наш клик-по-полю — это тот же jump-to-source,
только вместо кода открывается поле. Берём мысль: превью должно быть
первичным, код не показываем вовсе.

**AI loading states (uxpatterns.dev).** Явные состояния запроса: ожидание,
работа, стриминг, готово, прервано, ошибка; статус-лейбл рядом с
затронутым контентом; ошибки различать по типу (лимит токенов, недоступность,
частичный результат) и предлагать следующее действие. Мы стрим не можем
(инструменты выполняются пачкой), поэтому показываем стадии и время.
«Показывать вызовы инструментов по мере выполнения» — у нас это список
правок в ответе; сделать его человеческим (номера и названия слайдов).

## 5. Первая итерация (сделано 2026-09-08)

По приоритету боли из скриншотов и сегодняшнего прогона:

1. Страница колоды в три зоны (R3), лента миниатюр, выбранный слайд,
   исправление переполнения левой колонки.
2. Состояние генерации со стадиями и скелетонами (R4).
3. Вложения в чате и чипы подсказок (R7), человеческий список правок,
   подсветка изменённых слайдов (R8).
4. Обнаруживаемость правки: подсветка полей при наведении на слайд (R5).
5. Панель свойств без JSON (R6).
6. Каталог: поиск и удаление в корзину (R1), дропзона и чипы примеров (R2).
7. Тосты вместо alert/confirm (R10), кнопки колоды (R9).

Сделано всё из списка выше, плюс переименование по клику на название,
копирование ссылки, «Вернуть» в тосте после удаления слайда. Проверено
скриншотами в headless Chromium (Playwright в Docker) на 1366×850: главная,
колода, панель свойств, редактор поля, состояние сборки.

Отложено: режим «Сначала план» (нужна отдельная ветка агента), «Откатить эту
правку» у сообщения (есть история версий), поиск по содержимому слайдов.

## 6. Вторая итерация (сделано 2026-09-08, вечер)

Боковое меню как в DeepSeek на всех страницах: «Новая презентация», разделы
«Мои презентации», «История обращений», «Мои шаблоны», список недавних колод
по дням (Сегодня / Вчера / На этой неделе / Раньше), статус подключённой
модели внизу. На странице колоды меню свёрнуто в полоску иконок, состояние
запоминается в localStorage.

- «История обращений» — все запросы пользователя к модели по всем колодам,
  по дням, с поиском и переходом к колоде (`GET /api/history`).
- «Мои шаблоны» — шаблоны с сервера (`template/` плюс `templates/<id>/`),
  превью шести типов слайдов рендерится образцом и кешируется; выбор шаблона
  на форме создания и в агентском API. Загрузки шаблонов через интерфейс нет
  намеренно: шаблон — код, его кладут в репозиторий.
