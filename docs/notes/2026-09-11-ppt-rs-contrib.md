# ppt-rs: что мешает использовать его в typst-deck и как бы мы контрибьютили

Дата: 2026-09-11. Статус: заметка, в upstream ничего не отправлено.

Контекст: для экспорта колоды в редактируемый PPTX на корпоративном мастере выбран
python-pptx. ppt-rs (<https://github.com/yingkitw/ppt-rs>) рассматривался как
альтернатива; ниже — почему он не подошёл, что именно в нём пришлось бы исправить
и как это предложить автору.

## Проект

- Rust-крейт + CLI `pptcli` (фича `cli`) + MCP-сервер `ppt_mcp` (фича `mcp`),
  лицензия Apache-2.0. Привязок к Python нет.
- ~41 тыс. строк в 156 файлах, версия 0.2.26, первый релиз 2025-11, релизы раз в
  несколько дней. Один автор (yingkitw), 49 звёзд, 8 форков.
- Помимо генерации: импорт Markdown/HTML, web2ppt, экспорт в PDF, MCP.

## Что проверили (2026-09-11, коммит c2aeae0)

```sh
cargo build --release --features cli --bin pptcli   # без --features cli бинарник не собирается
pptcli create out.pptx --title "Проверка" --slides 3 --template <мастер 677×381 мм, 10 макетов>
```

Результат:

| что | ожидали | получили |
|---|---|---|
| размер слайда | как в шаблоне, 677×381 мм | 254×190 мм (4:3, зашит) |
| макеты | 10 из шаблона | скопированы все 10 |
| макет слайдов | титульный для первого | все три — макет №2 |
| заголовок и тело | заполнители макета, геометрия из мастера | фигуры без `<p:ph>`, на координатах Office (13,8 и 13,44 мм) |

Итог: с чужим мастером `--template` переносит оформление, но не раскладку —
текст не попадает в зоны мастера, а размер слайда не совпадает с мастером.

## Как контрибьютить

Правил в репозитории нет: ни CONTRIBUTING, ни шаблонов issue/PR, ни CI. Значит,
обычный порядок GitHub, но с поправкой на то, как проект живёт сейчас:

- **Ни одного внешнего PR не слито.** PR #7 (размер слайда, решает issue #6) висит
  с 2026-04-03 без ответа, #8 закрыт без слияния, #3 открыт. Поэтому начинать с
  issue, а не с PR: описать проблему с воспроизведением и прямо спросить, примет ли
  автор правку и в каком виде.
- **Малые PR, по одному на проблему,** с тестами. CI нет — перед отправкой локально
  `cargo fmt --check`, `cargo clippy --all-features`, `cargo test --all-features`.
  Отдельно проверить сборку с `--no-default-features`: она сейчас сломана (issue #11).
- **Лицензия.** Apache-2.0, раздел 5: вклад принимается на тех же условиях, CLA нет.
- **Воспроизведение без корпоративных файлов.** Корпоративный мастер в issue не
  прикладывать. Для репро собрать синтетический шаблон (например, python-pptx:
  слайд 16:9 нестандартного размера и макет с нестандартным заполнителем idx=21).
- **Не дублировать.** По размеру слайда уже есть #6/#7 — лучше отревьюить и
  поддержать #7, дописав в него случай с шаблоном, чем открывать своё.
- Если автор не отвечает, форк под своим именем имеет смысл только при реальном
  использовании в typst-deck. Сейчас его нет: экспорт делаем на python-pptx.

## Черновики issue

Порядок — от малого к большому; I2 и I4 зависят друг от друга, I1 пересекается с #7.

### I1. `--template` не берёт размер слайда из шаблона

- **Проблема:** `package_xml.rs:357` всегда пишет
  `<p:sldSz cx="9144000" cy="6858000" type="screen4x3"/>`. С шаблоном другого
  размера мастер и макеты рассчитаны на одну геометрию, слайды — на другую.
- **Ожидание:** при `--template` размер слайда (и `p:notesSz`) копируется из
  `ppt/presentation.xml` шаблона; без шаблона — из настроек (как в PR #7).
- **Правка:** `generator/template.rs` читает `p:sldSz` шаблона; запись
  `presentation.xml` в `generator/builder.rs` (строки ~748 и ~848) берёт размер оттуда.
  Небольшая; оформить комментарием/коммитом к PR #7.

### I2. Слайды не используют заполнители макета

- **Проблема:** `generator/slide_xml/layouts.rs` (`create_title_and_content_slide`,
  `create_two_column_slide` и др.) пишет заголовок и тело фигурами с жёсткими
  координатами Office по умолчанию (`<a:off x="457200" y="274638"/>` и т. п.);
  настоящий заполнитель есть только у `ctrTitle` в `slide_xml/mod.rs`. С шаблоном
  текст не наследует ни положение, ни стиль из макета.
- **Ожидание:** если у выбранного макета есть заполнители, слайд ссылается на них
  (`<p:ph type="title"/>`, `<p:ph idx="1"/>`) с пустым `<p:spPr/>`, и геометрия
  с оформлением наследуются из макета. Явные координаты — только для Blank или
  когда заполнителя нет.
- **Правка:** средняя по объёму, затрагивает ядро генератора слайдов; нужны тесты
  «шаблон с нестандартной геометрией → у фигур нет `a:off`, есть `p:ph`».

### I3. Макет выбирается только из 7 фиксированных номеров, промах молчит

- **Проблема:** `SlideLayout` (`generator/slide_content/layout.rs`) — перечисление
  из 7 вариантов с номерами 1–7; `PptxTemplate::resolve_layout_number`
  (`generator/template.rs`) при отсутствии макета молча возвращает 1. В шаблоне с 10
  макетами №8–10 недоступны, а номер не говорит, какой это макет.
- **Ожидание:** выбор макета по номеру и по имени (`<p:cSld name="…">`); ошибка,
  а не откат, если макета нет; команда `pptcli layouts template.pptx` со списком
  макетов и их заполнителей.
- **Правка:** варианты `SlideLayout::Index(usize)` и `SlideLayout::Named(String)`,
  резолв по имени в `template.rs`, флаг `--layout` в CLI. Небольшая.

### I4. Нет способа заполнить заполнитель по номеру

- **Проблема:** в API есть заголовок, пункты и фигуры по координатам, но не
  «положить текст в заполнитель idx=N». Корпоративные макеты держат в нестандартных
  заполнителях автора и дату, контакты, подписи.
- **Ожидание:** `SlideContent::placeholder(idx, text)` (и вариант с абзацами).
- **Правка:** после I2; средняя.

### I5. Цвет серий и точек графика не задаётся

- **Проблема:** `ChartSeries` (`generator/charts/data.rs`) — только `name` и
  `values`; в `generator/charts/xml.rs` нет ни цвета серии, ни `c:dPt`, ни
  `c:invertIfNegative`. Палитру бренда и отдельный цвет отрицательных значений не
  задать.
- **Ожидание:** `ChartSeries::with_color("#RRGGBB")`, цвета отдельных точек и
  опция цвета для отрицательных значений.
- **Правка:** небольшая–средняя; тесты на XML серии.

### Мелочь

`pptcli create` кладёт все слайды на один макет (№2), включая первый; при
шаблоне первый слайд логично класть на титульный макет. Упомянуть в I3.

## Что нужно, чтобы typst-deck мог перейти на ppt-rs

I1–I5 в upstream плюс способ звать его из Python: привязки (PyO3) или вход
`pptcli from-json <spec>` с описанием слайдов, макетов и заполнителей. Пока этого
нет, python-pptx закрывает задачу целиком.
