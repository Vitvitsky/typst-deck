# typst-deck

Корпоративный генератор презентаций: чат с корпоративной нейросетью плюс
живое превью слайдов в корпоративном Typst-шаблоне. Сотрудник описывает
презентацию текстом или кидает Word/Excel/CSV, правит результат через чат
или кликом по слайду, скачивает PDF или редактируемый PPTX. Тот же сервис
доступен чат-боту как инструмент: «сделай презентацию по файлу» → PDF плюс
ссылка на доработку.

Замена внешним сервисам (Gamma, DeepSeek) для сценария «сделай презентацию»
внутри корпоративной сети.

## Принцип

**Нейросеть не пишет Typst-код.** Источник истины — модель презентации
(JSON): список слайдов, у каждого тип из закрытого набора (15 типов: титул,
повестка, раздел, тезисы, картинка, блоки, сравнение, цитата, график, два
графика, метрики, таблица, галерея, видео, финал) и поля этого типа. Python детерминированно превращает модель в `.typ` и
компилирует. Нейросеть и человек правят одну и ту же модель точечными
патчами; каждая правка — новая версия с откатом.

```json
{
  "slides": [
    {"type": "title", "title": "Итоги квартала", "subtitle": "Финансы, Q3"},
    {"type": "image", "title": "Рост выручки", "bullets": ["…"],
     "image": "a3f9k2q.png", "image_size": "large"},
    {"type": "chart", "kind": "bar", "title": "Продажи по регионам",
     "labels": ["Центр", "Север"], "series": [{"name": "млн", "values": [42, 17]}]},
    {"type": "final"}
  ]
}
```

## Куда встраивается

Сервис — шаг «оформить» в любом процессе, где содержание презентации уже
есть или его можно описать словами. На входе — задание текстом и файлы
(`.txt`, `.md`, `.docx`, `.xlsx`, `.csv`, картинки), на выходе — PDF,
редактируемый PPTX (у шаблона с PowerPoint-мастером) и ссылка на доработку в
браузере. Вызов — HTTP, подробности — [docs/api.md](docs/api.md).

- **Чат-бот или ассистент.** Пользователь просит «сделай презентацию по
  файлу», бот зовёт `POST /api/agent/create_deck` и отдаёт PDF и `edit_url`.
  Правки — `POST /api/agent/revise_deck` с текстом просьбы.
- **Структура уже известна.** Другая система или аналитик заранее знают, какие
  слайды нужны: отправляют их списком в `brief` («1. Титул: …; 2. Выручка по
  кварталам — столбцы из файла; 3. Выводы: …») вместе с данными. Модель
  раскладывает это по типам слайдов шаблона и укладывает текст в ёмкость
  слотов, числа для графиков берёт из файлов. Дословность текста не
  гарантирована: модель может сократить формулировку под предел поля.
- **Регулярные отчёты.** Скрипт или планировщик раз в период выгружает данные
  в `.xlsx`/`.csv` и создаёт колоду тем же вызовом; ответственный получает
  ссылку и дошлифовывает руками или чатом.
- **Самостоятельная работа сотрудника.** Веб-интерфейс: описал, приложил
  файлы, поправил кликом по слайду или в чате, скачал.

Во всех сценариях презентация собирается в корпоративном шаблоне: вид задаёт
шаблон, а не модель, поэтому результат одинаково оформлен, кто бы его ни
заказал.

Чего пока нет: сборки из готовой модели колоды (JSON) без нейросети — каждое
создание проходит через модель; MCP-обёртки над агентским API; разграничения
доступа по пользователям. Всё это — в [бэклоге](docs/backlog.md).

## Как расширять

Расширения ложатся в заранее разведённые места; код ядра для большинства из
них трогать не нужно.

| Что добавить | Где и сколько работы |
|---|---|
| Корпоративный шаблон | Без правок кода: репозиторий канона по [контракту](docs/template-contract.md), монтирование вторым корнем. |
| Экспорт PPTX для шаблона | Без правок кода: PowerPoint-мастер и `pptx.json` в шаблоне. |
| Другой провайдер модели | Без правок кода: `TYPST_DECK_LLM_*` в `.env`; любой OpenAI-совместимый API, без tool calling — режим `json`. |
| Новый вход (формат файла) | `extract.py`: функция извлечения текста и строка в разборе расширений. |
| Новый тип слайда | Модель (`model.py`), рендер (`render.py`), контракт и функция в каждом шаблоне, сопоставление PPTX — см. [ADR 0018](docs/adr/0018-fifteen-slide-types.md). |
| Новый формат выдачи | Модуль рядом с `pptx.py` и маршрут в `api/decks.py`: на вход — та же модель колоды. |
| Новый инструмент модели | `llm/tools.py` и описание в `llm/prompt.md`; проверка — через ту же модель и `slots.py`. |
| Новый канал вызова (MCP, очередь) | Тонкая обёртка над `service.py`, как `api/agent.py`. |

Почему устроено именно так — [журнал решений](docs/adr/README.md).

## Быстрый старт

Нужны `uv` и `typst` 0.15+ в PATH.

```sh
uv sync                        # окружение
cp .env.example .env           # и вписать ключ модели
uv run pytest                  # встроенные шаблоны; корпоративные тесты пропускаются
TYPST_DECK_TEST_TEMPLATES=~/corp-templates uv run pytest   # плюс тесты корпоративных шаблонов
scripts/dev.sh                 # http://127.0.0.1:8000 с автоперезагрузкой
```

`scripts/dev.sh` берёт `DEEPSEEK_API_KEY`, `DEEPSEEK_API_BASE`,
`DEEPSEEK_MODEL` из `~/stack/.env`, если они не заданы, и подключает
корпоративные шаблоны из `~/corp-templates`.

## Настройка

Переменные с префиксом `TYPST_DECK_` — из окружения или из `.env` в текущем
каталоге; полный список с пояснениями и значениями по умолчанию —
[`.env.example`](.env.example). `DEEPSEEK_API_KEY`, `DEEPSEEK_API_BASE`,
`DEEPSEEK_MODEL` принимаются из окружения как синонимы `LLM_*`. Без ключа
сервис стартует, работает ручная правка, генерация отвечает 503.

## Шаблоны

В образе и в этом репозитории — только встроенные шаблоны `default`
(`template/`, он же эталон контракта) и `dark` (`templates/dark/`).
Корпоративный шаблон живёт в репозитории своего канона и подключается
монтированием вторым корнем шаблонов: как сделать совместимый шаблон,
проверить его и подключить, как задать ёмкость слотов и PowerPoint-мастер для
экспорта в PPTX — [`docs/template-contract.md`](docs/template-contract.md).

## Устройство репозитория

```
src/typst_deck/     сервис: модель, рендер, хранилище, LLM-агент, API, статика
  api/              маршруты FastAPI
  llm/              клиент, инструменты, цикл агента, системный промпт
  static/           интерфейс без сборки (ES-модули)
  typst/fields.typ  маркеры полей для кликов по превью
template/           шаблон default — эталон контракта
templates/dark/     встроенный шаблон dark
scripts/            dev.sh — локальный запуск; measure_slots.py — замер ёмкости слотов
tests/              pytest; tests/golden — эталонный .typ
docs/               документация, бэклог, решения — см. ниже
DESIGN.md           правила интерфейса
Dockerfile          образ сервиса (podman читает как есть)
```
