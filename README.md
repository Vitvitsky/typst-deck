# typst-deck

Корпоративный генератор презентаций: чат с корпоративной нейросетью плюс
живое превью слайдов в корпоративном Typst-шаблоне. Сотрудник описывает
презентацию текстом или кидает Word/Excel, правит результат через чат или
кликом по слайду, скачивает PDF.

Замена внешним сервисам (Gamma, DeepSeek) для сценария «сделай презентацию»
внутри корпоративной сети.

## Принцип

**Нейросеть не пишет Typst-код.** Источник истины — модель презентации
(JSON): список слайдов, у каждого тип из закрытого набора шаблона и поля
этого типа. Python детерминированно превращает модель в `.typ` и
компилирует. Нейросеть и человек правят одну и ту же модель.

```json
{
  "slides": [
    {"type": "title", "title": "Итоги квартала", "subtitle": "Финансы, Q3"},
    {"type": "image", "title": "Рост выручки", "bullets": ["…"],
     "image": "assets/a1.png", "image_size": "large"},
    {"type": "bar-chart", "title": "Продажи по регионам",
     "data": [["Центр", 42], ["Север", 17]]},
    {"type": "final"}
  ]
}
```

## Архитектура

```
браузер ── чат ──▶ FastAPI ──▶ LLM (корп. DeepSeek) через инструменты
   ▲                 │              create_deck / update_slide / add_slide /
   │ SVG-превью      │              move_slide / remove_slide
   │ клик по полю    ▼
   └──────── модель колоды (JSON) ──▶ render.py ──▶ deck.typ
                                        │
                                  typst compile ──▶ SVG (превью) / PDF (скачать)
                                  typst eval query ──▶ координаты полей для кликов
```

Компоненты:

- `backend/` — FastAPI: хранение колод, рендер `.typ`, вызовы `typst`,
  прокси к LLM, загрузка файлов и картинок.
- `template/` — корпоративный Typst-шаблон: функции типов слайдов,
  SVG-ассеты, шрифты. Рядом с каждым редактируемым полем шаблон ставит
  `metadata` с `here().position()` для `query`.
- `frontend/` — чат слева, превью справа (~68% ширины), клик по полю
  на слайде открывает правку.

## Агентная форма

Сервис доступен не только из своего веб-интерфейса, но и как инструмент
корпоративного чат-бота: «сделай презентацию по этому файлу» → бот вызывает
сервис → в чат приходит PDF и ссылка «доработать», которая открывает ту же
колоду в веб-интерфейсе.

Следствие для архитектуры: **веб-интерфейс и чат-бот — два клиента одного
API, а колода — сессия с постоянным адресом.** Ни одна функция не живёт
только в UI.

Инструменты для бота крупные, про слайды бот не знает:

- `create_deck(brief, files[]) → {deck_id, pdf_url, edit_url}`
- `revise_deck(deck_id, request) → {pdf_url, edit_url}` — правка словами
  («на третьем слайде другой заголовок»), внутри тот же цикл, что и в
  чате веб-интерфейса
- `get_deck(deck_id) → {pdf_url, edit_url, outline}`

Генерация и мелкие правки (`update_slide` и т.п.) остаются внутри сервиса:
он сам ходит к LLM со своим системным промптом и знанием шаблона. Бот
только передаёт задание и получает результат, поэтому его модель может быть
любой, лишь бы умела вызывать инструменты.

Как отдать инструменты боту:

- **MCP-сервер** поверх того же бэкенда, если бот умеет MCP (Hermes на этом
  сервере, Claude, Cursor). Основной путь.
- **OpenAI-совместимая схема функций** для ботов без MCP: три JSON-схемы
  и REST под ними, то же самое без обёртки.

`edit_url` вида `/deck/d/{deck_id}?t=<токен>`: подписанный токен даёт доступ
к колоде без входа на первом этапе, при корпоративном SSO заменяется на
проверку пользователя. Долгая генерация идёт как задача: `create_deck`
возвращает `deck_id` сразу, бот опрашивает статус или получает готовый
результат через `get_deck`.

Для демо на этом сервере бот — `hermes` или `deepseek-web` из `~/stack`,
подключённые к typst-deck по внутренней сети.

## Типы слайдов (первая версия)

Закрытый набор, без сырого Typst внутри слайдов:

- `title` — заглавный
- `section` — промежуточный/разделитель
- `image` — заголовок, буллеты, картинка с параметром размера
- `bar-chart` — бар-чарт из таблицы
- `chart` — график
- `final` — финальный

Всё, что нельзя выразить параметрами, в первой версии не делается.
Просьбы, которые не уложились, собираются из логов чата и идут в шаблон.

## Требования

- Python 3.12+
- `typst` CLI 0.15+ (на сервере стоит 0.15.1 в `~/.local/bin`); координаты полей берутся `typst eval 'query(<edit>).map(it => it.value)' --in deck.typ`, старый `typst query` объявлен устаревшим
- доступ к корпоративному LLM-эндпоинту (OpenAI-совместимый API)

## Открытые вопросы

- Умеет ли корпоративный эндпоинт tool calling или только JSON-режим.
- Графики: cetz/lilaq внутри шаблона или внешний рендер в SVG.
- Хранение колод и аутентификация на первом этапе.

## Демо на этом сервере

План, когда появится рабочий прототип. Стек в `~/stack` устроен единообразно,
typst-deck встаёт в него тем же способом, что и `deepseek-web`:

- сервис `typst-deck` в `~/stack/compose.yaml`, порт `127.0.0.1:8088:8000`,
  сеть `internal`, healthcheck на `/api/health`;
- образ на `python:3.12-slim` с бинарником `typst` и шрифтами шаблона внутри;
- ключ и адрес модели из уже существующих переменных `.env`:
  `DEEPSEEK_API_KEY`, `DEEPSEEK_API_BASE`, `DEEPSEEK_MODEL`. Публичный
  DeepSeek играет роль «корпоративной» модели, эндпоинт OpenAI-совместимый,
  поэтому замена на внутренний это смена двух переменных;
- путь `/deck/` в `nginx/portfolio.conf` по образцу `/deepseek/`: Basic Auth,
  лимиты, Nginx срезает префикс. Фронтенду нужен относительный base path;
- колоды и загруженные файлы в volume `typst-deck-data`, снаружи ничего
  не пишется.

Ограничение для публичного демо: картинки по ссылке из интернета качает
бэкенд, значит нужен allow-list доменов или отключение этой функции.
